# 머신러닝기초 복습팩 문제설명 자동 연결 및 과거 팩 생성 설계

## 확정 의도

복습팩 신규 생성과 기존 팩 갱신에서 최종 복습문제 전체의 문제설명 HTML·MD를 함께 생성한다. 사용자 결정 #6은 **과거 모든 복습팩에도 일괄 생성 [confirmed]**이다. 나머지 결정은 앞선 grill-yourself 설계의 권장값을 유지한다. 이번 변경은 기존 두 스킬을 연결하는 bounded 작업이다.

## 실행 경계

- 실제 이름은 `ml-problem-explain`이다. `.agents/skills/*`은 `.claude/skills/*`으로 연결된 심볼릭 링크이며 실체만 수정한다.
- 복습팩 생성 시작 전에 형제 설명 스킬의 `SKILL.md`와 `scripts/mpe_cli.py` 존재를 확인한다. 누락 시 경로·원인을 보고하고 시작하지 않는다.
- 기본 팩 HTML·MD·PDF 쌍·그림의 기존 검증과 배포를 완료한 직후, 보고 전에 설명 스킬 전체 절차를 실행한다.
- 입력은 방금 배포한 복습문제 HTML의 정확한 절대 경로다. 날짜·최신 팩 선택에 맡기지 않는다.
- 신규·기존 갱신·lite 모두 같은 연결을 사용한다. PDF 비율만 바꾸는 별도 마이그레이션은 복습문제 갱신으로 간주하지 않는다.
- 갱신은 최종 전체 문항·소문항의 설명을 재생성한다. 부분 해설을 전체 완료로 보고하지 않는다.
- 설명 CLI는 저작기가 아니다. extract → 원자료 읽기 → 전체 조각 저작 → 독립 검산 → build/check → 네 실제 검토 → publish를 수행한다.

## 전역 제약

- Python 3.10 이상, 설명 실행기는 표준 라이브러리만 사용한다.
- 설명 순서는 `understand → recall → start → solve → verify → pitfall → retry`이다.
- 문체는 `~해요` 체와 영어 전문용어 병기이다.
- 모든 문항·소문항에 답·가정·단계별 이유·검산과 우측 요약을 작성한다.
- `source_visual/content/independent/browser` 네 실제 검토는 lite에서도 생략하지 않는다.
- 브라우저 검토는 1280×900/375×812, light/dark에서 전체 문항을 확인한다.
- 콘솔·KaTeX 오류·누락 자원·외부 요청·문서 가로 넘침은 0이어야 한다.
- 짧은 인라인 수식 스크롤과 보이는 수식 스크롤바는 0이며 긴 수식은 의미 단위 줄바꿈을 우선한다.
- 현재 입력·참조·조각·산출물 해시와 실제 검토를 묶는다. 합성 승인이나 해시만 바꾸는 재승인은 금지한다.
- backfill은 원 복습문제·정리노트 HTML/MD·PDF·기존 그림·과제·은행·교재를 수정하지 않는다.
- 설명 소유 파일만 고유 백업 후 교체하며 교체 실패 시 복구한다.
- 실패 시 검증된 기본 팩과 이전 설명을 보존하고 “복습팩 생성됨 / 문제설명 보류”로 보고한다.
- 이전 설명을 보존하더라도 갱신된 문제에 대한 검증 완료로 표시하지 않는다.
- 모호함·답 충돌·원문 미확인은 팩 단위 disputed로 보류하고 다른 독립 팩은 계속한다.
- 정리노트·복습문제에 설명 링크를 자동 삽입하지 않는다. 설명에서 원 문제·개념으로 연결한다.
- 새 문제·설명 PDF·영상은 생성하지 않는다. 커밋·푸시는 별도 사용자 지시가 있을 때만 수행한다.

## 과거 팩 범위

2026-10-13 계획 작성 시 read-only `load_source`로 아래 9팩 모두 추출 가능함을 확인했다. 검토 단위는 각 문제의 subparts 합이며 단일 문항은 main 1개로 센다. 아직 수학 검증이나 설명 생성은 수행하지 않았다.

실행 시작 때 목록과 SHA-256을 다시 확정한다. 날짜 오름차순의 명시 경로마다 독립 RUN을 사용한다. 0909를 대표 팩으로 먼저 발행·검증하고 나머지 8팩을 처리한다. backfill은 ml-review-pack을 재호출하여 문제를 다시 만들지 않는다. 현재 과제1 설명은 보호 대상이다. 입력이 추가·삭제되면 inventory 변경을 보고하고 현재 실제 복습문제 전체를 범위로 사용하며 수량을 맞추기 위해 문제를 만들지 않는다.

## 완료 조건

1. 스킬 연결 규칙과 테스트가 신규·갱신·lite의 전체 설명 절차를 보장한다.
2. 실행 당시 inventory의 모든 팩에 전체 문항 설명 HTML·MD와 설명 소유 자료가 발행되거나, 팩별 보류 이유가 명시된다. 보류가 있으면 전체 완료라고 주장하지 않는다.
3. 실제 원자료 대조·내용·독립 검산·브라우저 근거가 현재 산출물에 묶인다.
4. 보호 파일과 기존 과제1 설명의 bytes/SHA-256이 기준선과 일치한다.
5. 현재 발행 경로의 모든 로컬 자원·원 문제·개념 anchor가 존재하고 HTML·MD 문항/소문항이 입력과 일치한다.
