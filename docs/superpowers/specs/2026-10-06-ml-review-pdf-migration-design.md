## 템플릿과 출력

전자회로2 workbook/templates/problem.html, answer.html을 그대로 복사한다.
원본 CSS·JS·문구·로고 표기·색상·글꼴·페이지 틀·필기 격자·Hint 처리·자동 맞춤을 변경하지 않는다.
데이터 자리표시자 __WORKBOOK_DATA__ 치환만 생성된 HTML에 적용한다.
2026-10-06 확인 SHA-256:
- problem.html: 431fdafcd3bce6d86b2bb7881ed4332e6287a9b8c6bd8626628f9e673a4d2655
- answer.html: 4d3a13379d759ae8b1b48dd27417919929b4e0bf94a686a7362b79719e949040

실행 시 원본이 바뀌었으면 기록된 해시와 혼합하지 않는다. 같은 원본 버전의 두 파일을 다시 확인하고 provenance와 테스트 기대값을 함께 갱신한다.
ML 폴더만으로 다시 빌드할 수 있어야 하며, 실행 때 EC2 폴더를 요구하지 않는다.

문제 PDF: 왼쪽 원문·조건·구할 것, 가운데 그림과 점 격자 필기 공간, 오른쪽 기존 힌트.
답안 PDF: 동일한 문제 배치, 가운데 단계별 풀이와 최종 답, 원본 템플릿의 상세 Hint 페이지.
PDF는 검색 가능한 한국어 본문과 렌더링된 수식을 유지한다. 표·그림만 독립 그림으로 만든다.

## 데이터 변환

기존 HTML을 정본 입력으로 읽는다. 실행된 DOM에서는 details가 다른 패널로 이동하므로 저장된 원시 HTML을 읽는다.
문제 번호·순서·part·교과서 출처·원문 발췌·수치·변수·수식·그래프 관계·표 값·힌트·풀이 단계·정답을 보존한다.
문제 수는 article.card 수에서 계산한다. 제목·소개 문장에 적힌 수를 신뢰하지 않는다.

기존 47문항의 한국어 문제를 주어진 조건과 구할 것으로 구분한 편집용 layout JSON을 사람이 작성·대조한다.
자연어를 추측으로 자동 분할하지 않는다. 원문 조건과 질문을 분리·배치할 뿐 새로운 조건이나 답을 추가하지 않는다.
그림을 제외한 문제 문장은 공백·태그 정규화 후 기존 문장과 순서까지 대조한다.
표·그래프는 추출 전후의 값·라벨·화살표를 별도 대조한다.
향후 카드에는 problem 안에 conditions와 ask 블록을 작성하게 하여 같은 변환기를 사용한다.

템플릿 입력:
- kind: MML Example는 예제, MML Exercise는 연습문제.
- number: 날짜 내 기존 P1…PN. 날짜 간 내부 id 충돌은 pack 단위로 분리한다.
- section: 기존 MML 출처 식별자. 검증하지 않은 책 쪽·난이도를 새로 만들지 않는다.
- html.original: 기존 짧은 교과서 발췌. 원문 언어를 맞춘다.
- html.conditions / html.ask: 분리된 한국어 조건 / 질문.
- figures: 독립 PNG data URI와 mm 크기. source body의 같은 그림·표는 중복 표시하지 않는다.
- hints: 기존 힌트 전체. 띠에는 짧은 라벨, 상세 본문은 Hint 페이지.
- solution.steps: 기존 풀이 li 순서 그대로. label은 기존 제목이 없으면 빈 문자열.
- solution.answer: 기존 정답.
문제 모드의 payload에는 solution 키나 정답 본문을 넣지 않는다. 증명 대상 식은 질문이므로 유지한다.

숫자·행렬 결과는 기존 계산 도구 또는 독립 계산으로 재검증한다. 기호 유도는 전제와 단계별 변형을 대조한다.
원본 오류는 형식 변환 성공과 구분하여 보고한다. 문제가 발견되면 임의 문제 교체나 조용한 수정 없이 해당 pack의 출판을 보류한다.

## 그림·표와 페이지 분할

0916의 확률표, 0921의 방향 그래프, 0923의 4×4 역행렬, 0930의 긴 유도를 대표 사례로 삼는다.
표·SVG를 명시적 색상·선·라벨·폰트와 함께 300dpi 상당 PNG로 고정한다. 테마·원본 스타일 상속에 의존하지 않는다.
필수 그림은 각 문제 페이지에 포함한다. 그림이 너무 크면 템플릿의 기존 크기 계약 안에서 가독성을 확인한다.

기본 한 문제 한 페이지. 템플릿 자동 맞춤을 우선 사용한다.
남은 넘침은 문제 문장 블록·소문항·풀이 단계 경계에서 후속 페이지로 분리한다.
같은 템플릿을 사용하고 number에 계속을 표시한다. 내부 페이지 id는 p7-c2 같은 고유값을 쓴다.
logical_id와 물리 페이지 대응표를 검증 보고서에 기록한다. problem/answer 모드의 페이지 수는 달라도 된다.
수식·행렬·표·단일 풀이 단계 내부를 잘라 분리하지 않는다. 한 블록 자체가 들어가지 않으면 실패한다.
질문·필요한 조건은 후속 페이지에서도 해석 가능해야 한다. 답은 마지막 해설 페이지에 한 번만 표시한다.
유한한 분할 경계를 모두 사용한 뒤에도 넘치면 실패하고 기록한다. 임의 추가 축소나 내용 삭제로 통과시키지 않는다.

## 기존 자료·향후 스킬

날짜별 PDF 둘과 정리노트의 PDF 링크를 하나의 배포 단위로 검증한다.
생성·검사 중에는 별도 build-dir를 사용하고, 두 PDF와 링크가 준비된 후에만 공개 파일을 변경한다.
기존 HTML·Markdown·figures는 보존하며 정리노트 본문·수식·그림을 재작성하지 않는다.
정리노트에 문제지 PDF와 해설지 PDF를 추가하고 문항 수 안내는 실제 카드 수로 맞춘다.
동일 pack 재실행은 링크를 중복 추가하지 않는다. 실패하면 이전 PDF·노트 링크를 복구한다.
현재 HTML 조립·검사·Markdown API는 유지하고 PDF 빌드와 링크 연결 옵션을 추가한다.
향후 ml-review-pack에는 PDF 생성·검증을 필수 단계로 명시한다. 예습노트 공유 헬퍼의 동작을 보존한다.
PDF 링크는 Markdown 변환에서도 .pdf로 유지한다.

## 오류와 완료 기준

누락 필드·중복 id·원본 대비 조건 손실·정답 유출·그림 실패·KaTeX 오류·폰트 실패·넘침은 pack 출판 실패다.
data-ready=true와 body[data-overflow]만으로 충분하다고 보지 않는다. 답 영역·Hint·그림을 포함한 DOM 경계를 별도로 검사한다.
CDN이나 Chrome 오류는 실패로 보고하고 기존 자료를 유지한다. 이 작업에서 오프라인 폰트 패키지를 새로 설계하지 않는다.
47문항의 대응표, 총 14개 PDF, 날짜별 파일명, A4 가로 크기, 번호·순서·출처·풀이·정답 보존을 검사한다.
전체 PDF 페이지를 PNG로 렌더링하여 잘림·겹침·수식·표·그래프·필기 공간·Hint를 눈으로 확인한다.
기존 ML 및 ml-review-pack 테스트와 ml-preview-note 관련 회귀 검사를 통과한다.
검증 근거와 미해결 항목을 마이그레이션 보고서에 남긴다.
