# 문제별 떠올릴 개념과 공식 설계

## 의도와 결정

현재 `ml-problem-explain` 스킬과 기존 과제1 P1~P25 해설에 문제의 단서에서 개념과 공식을 선택하는 과정을 추가한다. 기존 기능 확장이다. 사용자가 처음 적은 `ml-explain-problem`은 저장소의 `ml-problem-explain`을 의미하며 이름은 유지한다.

앞선 대화의 결정 #5는 입문형으로 confirmed by default: 단서·개념의 뜻·공식·기호·적용 조건까지 설명한다. 사용자는 후속 메시지에서 writing-plans를 호출했고 다른 깊이를 지정하지 않았다. 이번 산출물은 구현 계획이며 실제 스킬/해설 변경은 실행 방식 선택 후 시작한다.

## 동작

- 각 문항의 설명 순서는 `understand → recall → start → solve → verify → pitfall → retry`이다.
- `recall`은 직계 `<div class="layer formal" data-explanation="recall">`이며 제목은 `이 문제를 봤을 때 떠올릴 개념과 공식`이다. 내용은 펼친 상태로 표시한다.
- 단서 → 개념의 뜻(영어 용어 병기) → 공식과 기호의 의미 → 적용 조건 및 이 문제에서 선택하는 이유를 연결한다.
- 새 구역은 일반 개념을 선택하는 과정, `start`는 실제 문제의 값·기호로 적는 첫 줄을 담당한다. 동일한 긴 설명을 복제하지 않는다.
- 필요한 개념 수를 고정하지 않는다. 소문항별 개념이 다르면 (a), (b) 등의 표지를 독자가 볼 수 있도록 붙인다. 공통 개념은 한 번만 설명한다.
- 우측 요약은 `summary-group` 안의 `떠올릴 개념·공식` 제목과 짧은 핵심을 추가한다. 본문을 통째로 복제하지 않는다.
- 공식이 적합하지 않은 정성/증명 문제는 판단 기준이나 정의를 설명한다. 없는 공식을 억지로 넣지 않는다.

## 전역 제약

- Python 3.10 이상, 실행기는 표준 라이브러리만 사용한다.
- 문체는 `~해요` 체와 영어 전문용어 병기이다.
- 기존 원 HTML·MD·PDF·그림을 수정하지 않는다. 갱신 대상은 설명 소유 산출물이다.
- HTML과 짝인 MD를 함께 재생성하고 설명 조각을 보존한다.
- 기존 과제1 P1~P25 전체를 갱신한다. 다른 날짜의 기존 해설은 일괄 수정하지 않는다.
- 새 문제·PDF·영상은 생성하지 않는다.
- 실제 공식·기호·적용 조건은 자료 대조와 내용 검토로 확인한다. 구조 검사만으로 수학 검증을 주장하지 않는다.
- 1280×900/375×812, light/dark에서 확인한다. 콘솔·KaTeX 오류·누락 자원·문서 가로 넘침은 0이어야 한다.
- 자원은 동봉된 로컬 KaTeX/Pretendard를 쓰며 외부 요청이 없어야 한다.
- 수정한 조각은 새 build와 실제 재검토를 거쳐 publish한다. 기존 검토의 해시만 바꿔 승인하지 않는다.
- 기존 설명 산출물은 백업하고 교체 실패 시 복구한다.

## 범위와 파일 경계

`.agents/skills/ml-problem-explain`은 `.claude/skills/ml-problem-explain`의 심볼릭 링크이다. 실제 파일은 `.claude` 경로로 수정한다. `SKILL.md`, 저작/검토 규칙, 계약 검사, 테스트가 미래 생성의 계약을 담당하고, 과제1 설명 조각이 문항별 교육 내용을 담당한다. 렌더러는 기존 조립/MD 변환을 활용하며 회귀 검증에서 문제가 확인될 때만 필요한 부분을 수정한다.

## 완료 조건

1. 새 생성에서 recall 누락·중복·빈 내용·잘못된 순서는 거부된다.
2. 기존 solve/verify의 모든 소문항 표지 검사는 유지된다.
3. HTML·MD·우측 요약에 추가 내용과 수식이 보존된다.
4. 과제1 25문항 모두 단서와 개념/공식의 연결, 기호, 적용 조건이 검토된다.
5. 원 자료는 보존되고 실제 검토에 묶인 산출물만 백업 후 발행된다.
