# 과제1 실제 발화·자막 재검증 설계

## 의도와 확정된 범위

사용자는 최근 과제1 발화·자막 검증 커밋이 있는지 물은 뒤 독립 재검증을 요청했다. grill-yourself의 선택 #4에 구체적인 변경값 없이 writing-plans로 진행했으므로 추천값인 수정 커밋 `c566d8905bf915e50c7f10ad617800fbc0a923e2`의 P1–P25를 기본 확정한다. 현재 폴더와 두 버전을 비교하는 작업은 포함하지 않는다. 다만 검사 입력을 식별하는 단계에서는 현재 파일의 SHA도 기록한다.

목표는 실제 전달 MP4의 음성에서 독립 전사를 얻고 원고·SRT·화면 자막과 대조하여 문항별 일치, 불일치, 미확인을 구분하는 것이다. 오류는 문항, 자막 구간, 원고, 실제 음성에서 얻은 전사, 화면 자막, 판정 이유를 함께 제시한다. 기존 원고를 다시 읽어 실제 음성을 검증했다고 하지 않는다.

분류는 architectural이다. 기존 기계적 타이밍 검사 밖에 독립 음성 인식과 근거를 연결하는 작은 검증 도구를 추가한다. 영상 제작 파이프라인과 공식 검수 상태를 바꾸지 않는다.

## 확인된 사실 — 2026-10-11

- 현재 브랜치 `codex/ml-problem-explain`에는 다른 작업의 미커밋 변경이 있다.
- 현재 최상위 과제1 MP4의 SHA 25개가 수정 전 목록과 일치하고 수정 커밋의 목록과 일치하는 파일은 0개다.
- 수정 커밋의 최상위 MP4 25개는 커밋의 검증결과 JSON SHA와 모두 일치한다. 정확한 RUN에는 manifest/timeline/SRT가 각각 25개다. 과거 백업 RUN을 포함한 재귀 검색은 중복을 만든다.
- 수정본에는 실측 자막 cue 744개가 기록되어 있다. P22가 가장 길며 약 365.97초다.
- 기존 `speech_chunks.verify_chunk_sync`는 PCM 길이·타임라인·SRT를 비교하며 파일을 쓴다. 직접 청취를 대신하지 않는다.
- 기존 `bundle_verify.meaning_review_passed`와 `chunk_review_passed`는 실제 청취의 `mode=live-listened` 및 모든 청크 검수 근거를 요구한다.
- Windows Python 3.14, FFmpeg/FFprobe, google-genai 2.25.0이 있다. 검사한 Python에는 faster_whisper/whisper/torch가 없다.
- 기존 `vertex_tts.load_key(env_file=None)`와 `live_transport(key, model)`를 인증·HTTP 전송에 재사용할 수 있다. TTS 전용 make_payload/_decode/synthesize는 사용하지 않는다.
- 현재 도구에는 에이전트가 로컬 음성을 직접 지각하는 입력 도구가 없다. 오디오 표시·내보내기는 청취 근거가 아니다.

## 접근과 완료 시 동작

독립 ASR 후 자막 대조 및 의심 구간 재확인을 사용한다. 원고·자막을 ASR 요청에 넣지 않는다. 실제 MP4 전체 음성을 전사해 누락·추가 발화를 찾고, 필요한 구간만 문맥을 포함해 재전사한다. 수학 표기 동등성은 문항별 근거로 검토한다.

결과는 네 축이다: ASR에 근거한 내용 대응, SRT/실측 시간의 기계적 대응, 실제 화면의 자막 대응, 직접 청취에 근거한 발음·자연스러운 연결·체감 동기화. 네 축을 하나의 통과로 합쳐 근거를 부풀리지 않는다.

## Global Constraints

- 대상은 `c566d8905bf915e50c7f10ad617800fbc0a923e2`의 P1–P25 MP4 25편과 자막 cue 744개다.
- 현재 브랜치·미커밋 변경·현재 MP4·기존 WAV·원본 PDF·공식 verification/report.json·publish/latest를 변경하지 않는다.
- Git 바이너리는 Python subprocess의 bytes로 추출한다. PowerShell 텍스트 파이프와 파일 리다이렉션을 통한 MP4 추출을 하지 않는다.
- 저장된 macOS 절대 경로는 사용하지 않는다. 커밋의 상대 listing 경로와 RUN 경로를 검증하여 새 snapshot 아래에 매핑한다.
- ASR 입력에는 MP4에서 추출한 음성과 일반 전사 지침만 넣는다. 기대 원고·자막·speech-pairs를 제공하지 않는다.
- 후보 ASR 모델은 `gemini-2.5-flash`, 기존 Vertex Express 전송 경로다. 실제 인증·모델·음성 입력 가능 여부는 P1 최초 전사 성공 전까지 미확인이다.
- 최초 전사 실패 시 전체 전사를 시작하지 않는다. 자동 모델 대체·새 계정 설정·전역 패키지 설치·TTS 재합성을 하지 않는다.
- 새 ASR 요청은 순차 실행하며 실행당 최대 50회다. 성공 결과는 음성 SHA·모델·지침·요청 설정에 묶어 재사용한다. 가격과 예상 비용을 추정하지 않는다.
- 숫자·부호·분수·변수·행열·조건·단위를 보존한다. 한글 일/이/삼 등의 전역 숫자 치환을 하지 않는다.
- SRT 반올림 오차 ≤1ms, 영상 경계 오차 ≤1프레임이다. 이는 시간 계산 검사 기준이며 ASR 시각 정확도나 실제 발화 동기화의 증명이 아니다.
- ASR 근거만으로 `mode=live-listened`, `complete=true`, `live_audio=verified`를 기록하지 않는다. 직접 청취 근거가 없으면 `complete=false`, `live_audio=unverified`다.
- 검증 결과는 별도 재검증 폴더에 보존하며 불일치와 미확인 구간을 모두 보고한다. 수정·재합성·머지·push는 이번 작업 범위에 포함하지 않는다.

## 조건부 실행 게이트

증거 게이트는 CONDITIONAL이다. 바이너리 추출과 입력 해시는 VERIFIED지만 ASR 가용성과 직접 청취는 UNRESOLVED다. P1 전사 smoke가 인증·음성 입력·JSON 응답을 확인해야 나머지 24편을 진행할 수 있다. 직접 청취가 계속 불가능하면 ASR 대조 보고서만 완성하고 그 한계를 최종 답변에 적는다. 음성 전사 자체가 불가능하면 실제 발화 검증 미실행으로 보고한다.

## 완료 기준

25개 영상 SHA와 744개 cue 신원을 고정하고, 가능한 모든 축을 실제 입력으로 검사한 재검증 보고서를 전달한다. 전사 또는 화면 검토 누락이 하나라도 있으면 해당 축은 unverified다. 보고서 생성 완료와 영상 검수 통과는 다른 상태다. content_status와 screen_status가 passed여도 직접 청취가 없으면 전체 complete는 false다.
