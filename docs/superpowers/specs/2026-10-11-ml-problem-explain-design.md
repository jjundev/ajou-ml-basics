# 머신러닝기초 문제풀이 입문 설명 설계

## 확정된 의도

논회실의 `문제설명.html` 기능만 머신러닝기초의 독립 로컬 스킬 `ml-problem-explain`로 구현한다. 이론은 읽었지만 문제풀이 경험이 부족한 학생에게 실제 첫 줄, 단계별 이유, 완성 답, 검산을 설명한다. 기존 복습문제와 과제를 모두 지원한다. 사용자 결정 #6은 **복습문제+과제 [confirmed]**이다. 나머지 설계 결정은 이전 대화의 추천값으로 확정한다.

## 범위와 호출

- `/ml-problem-explain 1007`: 날짜에 해당하는 복습문제 설명.
- `/ml-problem-explain 0909-0916`: 기간 안의 날짜별 팩을 각각 처리. 정확히 같은 이름의 통합 팩도 있으면 통합/개별 중 하나를 명시하게 한다.
- `/ml-problem-explain 과제1`: `과제/과제1/과제1_*.html` 카드 설명.
- `/ml-problem-explain <HTML 절대 경로>`: 명시한 복습문제 또는 과제 카드 파일 설명.
- 인자 없음: 파일 수정 시각이 아니라 파일명 날짜로 가장 최근 복습문제 선택. 과제를 자동 선택하지 않는다.
- 여러 후보를 임의로 합치지 않는다. 없는 대상과 모호한 대상은 후보 목록을 제시한다.
- 과제 PDF만 있으면 기존 카드 HTML 작성이 먼저 필요함을 안내한다. PDF 전사·카드 생성은 이번 스킬의 범위 밖이다.
- 문제 선별, 새 출제, 정리노트 생성, PDF 생성, 영상, 자동 채점, 기존 팩 자동 일괄 갱신은 제외한다.

## 입력과 원문 보존

저장된 HTML의 원시 카드가 기준이다. 기존 `review_pdf_cards.read_cards`와 `REVIEW`/`HOMEWORK` 프로필을 활용한다. 문항 ID, 번호, 순서, 제목, 조건, 질문, 그림, 모든 소문항을 유지한다. 카드의 기존 풀이·정답은 참고 답안이며 독립 검증을 대신하지 않는다.

구형 복습문제의 조건/질문은 `workbook/layouts/<range>_<slug>.json`으로 분리하되 `source_sha256`과 문항 집합이 입력과 일치해야 한다. 사용자의 원본을 고치지 않는다. 입력·참조 자료의 SHA-256을 기록하고 발행 직전에 변경 여부를 다시 확인한다.

## 설명 계약

각 문항은 `article.topic` 한 개, 원 문항 ID를 사용한다. 문제 읽기에는 원문 조건·구할 것·그림을 제공한다. 과제는 기존 카드의 영어 원문 전문도 유지한다. 설명에는 아래 여섯 구역을 모두 작성한다.

1. `understand`: 이 문제에서 할 일.
2. `start`: 첫 줄을 이렇게 시작해요. 실제 식·문장·표의 첫 행과 필요한 개념 링크.
3. `solve`: 왜 이렇게 푸는지 함께 따라가요. 각 식 변형의 이유·성질·가정.
4. `verify`: 완성 답과 실제 검산. 대입, 별도 계산, 특수 경우, 차원 확인 등 문제에 맞는 확인.
5. `pitfall`: 여기서 헷갈리기 쉬워요.
6. `retry`: 이제 설명을 닫고 다시 풀어요. 1~3개 체크리스트.

모든 소문항의 풀이와 답을 펼친다. 본문 풀이를 details/hidden으로 감추지 않는다. 직계 `.sum[hidden]`은 우측 요약용이며 시작·핵심 판단·검산만 재사용한다. 한국어 '~해요' 체, 한 줄에 한 수식 유도, 영어 전문용어 병기를 기본으로 한다. 행렬 차원, 확률의 조건과 정규화, 미분 대상과 적용 가정을 필요한 곳에서 설명한다. 단순 계산도 상징 계산·정확한 분수 계산 등으로 독립 검증한다. 증명·정성 문항은 논증과 조건을 수동 검토하고 계산 검증으로 표시하지 않는다.

MML, 강의자료, 기존 정리노트를 대조한다. STT는 필요할 때만 보조한다. 수업 밖 보충은 표시한다. 답 충돌·모호한 조건·미확인 원문은 기록하고 해당 팩 발행을 보류한다. 다른 날짜의 독립된 팩은 검증되면 발행 가능하다.

## 산출물과 UI

- 복습: `복습노트/<range>/문제설명_<range>_<slug>.html/.md`.
- 과제: `과제/과제<N>/과제<N>_문제설명_<slug>.html/.md`.
- 별도 그림 디렉터리: `figures_문제설명_<range>_<slug>/`, 과제는 range 대신 `hw<N>`.
- 생성 기록: `자료_문제설명_<range>_<slug>/manifest.json`, `validation.json`, 저작 조각과 사용한 검증 근거. 과제는 range 대신 `hw<N>`.
- 기존 노트 템플릿을 새 스킬로 복사해 사용한다. 목차는 문항별로, 이전/다음과 우측 요약, 다크모드를 유지한다.
- 읽음 상태 키는 `ml-problem-explain-<profile>-<range>-<slug>`이다.
- 의존 자원(KaTeX, Pretendard)은 스킬에 동봉해 설명 자료 디렉터리로 복사한다. 네트워크가 없어도 렌더링 가능하게 한다.
- 원 그림을 새 산출물의 자산으로 복사하고 참조를 바꾼다. 원 HTML/PDF/MD/그림을 수정하거나 삭제하지 않는다.
- 기존 정리노트에 자동으로 링크를 삽입하지 않는다. 새 설명에서 실제 존재하는 원 문제와 개념 토픽으로 링크한다.

## 구조

실체는 `.claude/skills/ml-problem-explain/`, `.agents/skills/ml-problem-explain`은 상대 디렉터리 심볼릭 링크로 등록한다. 기존 `ml-review-pack`의 파서·MD 변환기·파일 발행 함수를 좁은 어댑터로 재사용한다. 논회실 런타임·문제은행·실험 manifest는 가져오지 않는다. 새 템플릿과 설명 규칙은 새 스킬이 소유한다.

## 검증과 발행

매 실행은 새 `tmp/ml-problem-explain/<고유ID>/` 아래에서 작업한다. 대상별 stage를 분리한다. 입력 확인 → 원문 추출 → 저작 → 답 검증 → 조립 → 기계 검사 → 브라우저 검사 → 발행 순서다.

브라우저는 1280×900, 375×812와 두 테마에서 목차·이전/다음·요약·수식·표·그림·링크를 확인한다. 수식 오류, 깨진 자원, 콘솔 오류, 문서 가로 넘침은 0이어야 한다. 긴 행렬은 전용 수식 영역 안에서 스크롤할 수 있지만 페이지 전체 가로 넘침은 허용하지 않는다. MD의 문항 anchor·수식·이미지 링크 보존도 검사한다.

최종 보고서에는 원문 대조, 문항/소문항별 내용 검토, 독립 답 검증, 브라우저 검증을 별도 상태로 남긴다. 단순 구조 검사를 답 검증 통과로 취급하지 않는다. 모두 통과하고 입력 해시가 유지된 경우에만 새 설명 관련 파일을 백업 후 발행한다. 다중 파일 교체 도중 실패하면 이전 파일로 복구한다. 동시 발행은 기존 잠금 함수를 재사용해 거부한다.
