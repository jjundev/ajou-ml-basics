# 과제 1 문제설명 표시 수정

범위: ml-problem-explain 템플릿 및 과제 1 설명 HTML/MD. 원 과제 카드와 PDF, 수치 답과 증명 내용은 변경하지 않음.

## 원인과 변경

- 모든 인라인 KaTeX를 overflow:auto인 inline-block으로 만든 규칙은 1–2px의 조판 돌출에도 짧은 수식 스크롤바를 만들었다. 규칙을 제거하여 일반 수식을 원래 인라인 배치로 복원했다.
- eli5 층 전체의 margin/padding 0 규칙은 원문 뒤 understand와 마지막 retry 간격을 지웠다. 첫 직계 층만 예외로 두고 구역 24px, 제목 아래 12px, 소문항 16px 간격을 적용했다.
- 행렬을 각각 별도 줄에 배치하고 긴 식은 KaTeX의 관계 기호 사이 base 단위로 자연 줄바꿈한다. 더 나눌 수 없는 긴 식은 최대 15%만 축소한다. 그래도 넘치면 스크롤바 없이 키보드/터치로 이동할 수 있게 하고 안내를 표시한다. 수식 토큰을 재작성하거나 답을 생략하지 않는다.
- 가로 이동 영역은 화면 넘김의 키보드/터치 처리에서 제외하여 식을 읽다가 문항이 넘어가지 않게 했다.
- 요약은 제목과 본문을 의미별 그룹으로 묶었다. 첫 줄·주의점·답 사이 간격을 공통 규칙으로 처리한다.
- 원문 수치/식은 그대로 유지하면서 행렬 뒤 구두점이 별도 줄에 남지 않게 배치한다. 저작·검증 레퍼런스에 수식과 여백 규칙을 기록했다.

## 검증

regression.py는 수정 전 실제 발행 HTML에서 짧은 식의 스크롤 컨테이너 문제로 실패했다. test_layout.py는 새 템플릿을 실제 브라우저로 렌더링하여 짧은 식의 인라인 배치, understand/retry 간격, 원 행렬 표시와 문서 넘침을 검사한다.

첫 전체 표시 검사에서 자동 렌더링 span의 clientWidth=0을 읽어 짧은 식도 블록으로 바뀌는 문제를 발견했다. 폭 기준을 실제 문단/소문항으로 수정했다. 모바일 P15 본문의 긴 우도식은 글꼴 조정 직후 폭 검사와 다음 프레임의 조판 폭 사이에 6px 차이가 있었다. 다음 프레임에서 실제 돌출을 다시 측정해 필요한 수식만 이동 영역으로 처리했다. 최종 전체 결과는 layout-browser-results.json에 기록하며 failures=[]로 통과했다.

모든 25문항의 본문과 요약을 1280×900/375×812, 밝은/어두운 테마에서 검사한다. 100문항 화면과 100요약 화면에 대해 수식 스크롤바, 수식 잘림, 간격, 문서 가로 넘침, KaTeX/콘솔/자원 오류를 확인한다. 전치 원문 및 요약, P13·P17·P22·P25의 대표 화면을 이미지로 검토한다. 별도로 768/1024/1920 너비와 긴 수식의 화살표 동작을 확인한다.

layout-preservation.json은 이전에 검증한 모든 설명 조각의 해시와 전후 수식 토큰 일치를 기록한다. previous-review.json의 해시와 연결하고 원 입력 및 근거 파일 해시를 재확인한다. 수학 검증은 기존 independent.py/results/proof-review.md를 보존해 사용하며, 이번 표시 검사를 새로운 수학 검증이라고 주장하지 않는다.

최종 스킬 테스트 51개 통과, 생성 HTML 대상 Impeccable layout detector 결과 [] 및 git diff --check 통과. 768/1024/1920 추가 너비와 키보드 확인 통과. 발행은 승인 해시를 검증한 뒤 기존 파일을 백업해 교체한다.
