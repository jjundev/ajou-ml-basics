머신러닝(ML)이란?

사람·사물 인식, 사람 말 알아듣기처럼 규칙을 손으로 짜기 어려운 문제가 많아요. ML은 선형대수 · 확률 · 수치최적화 · 통계를 써서, 데이터(경험)로부터 자동으로 배우는 프로그램을 만드는 방법이에요.

종류무엇이 주어지나하는 일
지도학습 (supervised learning)정답(라벨)이 달린 예시정답을 맞히는 규칙을 배운다
비지도학습 (unsupervised learning)라벨 없는 데이터데이터 속 "흥미로운 패턴"을 찾는다 (예: 비슷한 것끼리 묶기)
강화학습 (reinforcement learning)환경(world)과 상호작용하는 agentscalar reward(점수 신호)를 최대화하도록 배운다

요즘 AI ≈ DNN(Deep Neural Network) ≈ Deep Learning이라고 할 만큼 신경망이 중심이에요. Universal Approximation Theorem: 신경망은 (충분히 크면) 일반적인 함수를 원하는 만큼 가깝게 흉내 낼 수 있는 "일반 함수 근사기"라는 정리예요.

1. 데이터 · 모델 · 러닝

머신러닝의 3요소: 데이터 · 모델 · 러닝

📅 0909L01 s5
🧸 쉽게 말하면

머신러닝은 요리 배우기예요. 재료(데이터), 레시피(모델), 연습(러닝) 세 가지가 있어야 해요.

연습을 잘 했는지는 처음 오는 손님에게 요리를 내 봐야 알아요. 이 손님이 바로 한 번도 못 본 데이터(unseen data)예요.

📐 정식 버전

머신러닝 시스템의 세 가지 주요 구성요소 (three major components, L01 s5):

  1. 데이터 (Data): $\{(\mathbf{x}_1, y_1), \dots, (\mathbf{x}_N, y_N)\}$ — 입력 벡터와 출력(라벨)의 쌍 N개.
  2. 모델 (Models): deterministic function(함수) 또는 probabilistic model(확률 모델).
  3. 러닝 (Learning): training(학습)과 prediction/inference(예측·추론).

좋은 머신러닝 모델 = unseen(학습에 쓰지 않은) data에서 잘 동작하는 모델. ML 알고리즘 = training을 잘 해서 prediction을 잘 하는 것.

ML이 요즘 "임계점"을 넘은 세 요인: ① 인터넷·모바일이 만든 방대한 데이터, ② 그걸 처리하는 GPU·NPU 컴퓨팅 파워, ③ 최적화(학습 파라미터 튜닝) 기술. 데이터가 적으면 inference(추론)의 정확도가 크게 떨어진다.

오늘의 메인 레슨: 머신러닝은 귀납이다

📅 0909L01 s5
🧸 쉽게 말하면

탐정은 발자국(데이터)을 보고 범인(규칙)을 추리해요. 이렇게 증거에서 규칙을 찾아내는 게 귀납이고, 머신러닝이 하는 일이에요.

반대로 "규칙(수식)을 먼저 알고 데이터가 어떻게 나올지 계산하는 것"은 연역이에요. 우리가 지금까지 배운 과목들은 대부분 연역이었어요.

📐 정식 버전
연역 (deductive)귀납 (inductive) = 머신러닝
먼저 주어지는 것원리 · 수식데이터 (raw data)
하는 일수식으로 데이터(출력)를 예측하고, 어긋나면 노이즈로 해석데이터를 가장 잘 설명하는 수식(규칙)을 스스로 만들어 냄
예인덕터 $v = L \frac{di}{dt}$, 통신 $y(t) = x(t) * h(t) + n(t)$점들을 보고 "선형 관계일 거야" → $y = \theta_1 x + \theta_0$

통신·신호처리 식 $y(t) = x(t) * h(t) + n(t)$ 에서 $*$ 는 convolution, $h(t)$ 는 임펄스 응답, $n(t)$ 는 노이즈다. $h(t)$ 를 알면 입력 $x(t)$ 로부터 출력 $y(t)$ 를 예측할 수 있다.

  1. 데이터(파란 점)가 주어진다. 그림에서는 점이지만 실제로 점 하나는 $D$차원 실수 벡터다.
  2. 경향을 본다: x가 커지면 y도 선형적으로 커진다.
  3. 모델을 정한다: $y = \theta_1 x + \theta_0$.
  4. $\theta_0, \theta_1$ 을 최적화한다. 이 과정이 학습이다.

데이터 = 벡터

📅 0909L01 s6
🧸 쉽게 말하면

컴퓨터에게 사진 한 장은 아주아주 긴 숫자 줄이에요. 그중 중요한 숫자만 남기면 짧은 줄이 되는데, 이 짧은 줄을 "데이터"라고 불러요.

📐 정식 버전

데이터셋 표기

$$\mathcal{D} = \{(\mathbf{x}_1, y_1), (\mathbf{x}_2, y_2), \dots, (\mathbf{x}_N, y_N)\}$$
  • 표기 관습 (convention): 볼드 소문자 $\mathbf{x}_n$ 은 벡터, $y_n$ 은 실수 하나(스칼라). 아래첨자 $n$ 은 n번째 데이터. 괄호로 묶은 $(\mathbf{x}_n, y_n)$ 은 짝꿍(세트)이다. 보통 입력은 $x$(벡터), 출력은 $y$(숫자)로 쓴다.
  • 빅데이터 = 데이터 개수 $N \to \infty$.
  • 차원: $\mathbf{x}_n \in \mathbb{R}^D$ — 실수 $D$개로 된 벡터. 예: $D = 3$ 이면 $\mathbf{x}_n = (x_{n1}, x_{n2}, x_{n3})$. 각 성분을 feature(또는 attribute, covariate)라고 부른다. $y_n$ 은 label(target, response variable, annotation)이라고 부른다.
  • 개/고양이 예시: 입력 사진은 (픽셀 수 × RGB 채널) 길이의 아주 긴 실수 벡터, 출력은 $y \in \{0,1\}$ (0 = 개, 1 = 고양이).

학습 방식

  • supervised learning: 라벨이 있다. 데이터가 $(\mathbf{x}_n, y_n)$ 쌍으로 주어진다.
  • unsupervised learning: 라벨이 없다. $\{\mathbf{x}_1, \dots, \mathbf{x}_N\}$ 만 주어진다. 비슷한 것끼리 묶는 clustering이 대표적이다.

raw data vs feature vector: 수십만 개 실수로 된 고화질 사진(raw data)을 1비트 결정(개냐 고양이냐)에 다 넣는 건 낭비다. 줄이고 줄여 만든 feature vector를 이번 학기에는 "데이터"라고 부른다. 이 과정을 (data) preprocessing, feature extraction이라고 한다.

  • PCA = principal(주요한) + component(성분) + analysis(분석): 결정에 정말 중요한 성분만 체계적으로 압축한다. 선형대수의 SVD(특이값 분해)나 고유값 분해(EVD)로 low-dimensional approximation(저차원 근사)을 만든다.
  • feature map / kernel: 반대로 원래 feature를 비선형으로 조합해 더 높은 차원의 벡터로 만든다.
  • autoencoder 같은 딥러닝 모델도 데이터를 통과시키며 스스로 feature extraction을 한다("누가누가 압축을 잘하나?").

모델 = 수식 (정답은 없다)

📅 0909 · 0914L01 s5–7
🧸 쉽게 말하면

모델은 "데이터가 왜 이렇게 생겼는지 설명하는 이야기"예요. 그 이야기를 수식으로 쓴 거예요.

더 잘 들어맞는 이야기는 있어도, 딱 하나의 "정답" 이야기는 없어요. 모델은 정답은 없고, 더 좋은 것과 덜 좋은 것만 있어요.

📐 정식 버전

모델 = 수식. 데이터 밑에서 동작하는 기작(규칙)을 수식으로 쓴 것이다. 공학수학에서 RLC 회로를 미분방정식으로 푼 것도 모델이다.

  • deterministic (함수) 모델: 자연법칙처럼 정해진 공식이 있다고 본다. 예: $F = ma$, "이 데이터는 $y = ax + b$ 일 거야"(1차식), "$ax^2 + bx + c$ 일 거야"(2차식). 3차식·지수·사인·로그도 가능하다. 계수 값은 나중에 fitting해 봐야 알지만 꼴(모양)은 먼저 정한다.
  • probabilistic (확률) 모델: 불확실성(노이즈)까지 모델에 넣는다. → 다음 토픽.

모델 셋업 예: $\mathbf{x} = (x_1, x_2, x_3)$ 이라 두고 $y = 3x_1 + 5x_2 + 6x_3 + 0.6$ 이라고 "자신감 있게 질러야 된다". 그리고 "왜 그렇게 생각했어?"에 합리적으로 답해 가는 과정이 모델 셋업이다. (여기의 3, 5, 6, 0.6을 좋은 값으로 맞추는 게 러닝이다.)

큰 모델은 작은 모델을 포함한다: $ax^2 + bx + c$ 에서 $a = 0$ 이면 1차식이 된다. 모델 크기(파라미터 수)가 커질수록 표현력도 커진다. 1차식이 안 맞으면 2차, 3차로 바꿔 본다.

suppose vs assume (0914)

  • assume: 사실이 아닌 줄 알면서 그렇다고 가정하는 것.
  • suppose: 모르니까 그렇게 추측하는 것. 모델을 고르는 일은 suppose다. "뉴럴넷으로 해 보니 잘 예측되던데? 그러면 되는 거야."

그래서 모델은 correct/incorrect의 문제가 아니라 good/bad, 즉 취사선택(preference)의 문제다.

영화 추천: 사람이 어떤 영화를 좋아하는지 그 속마음(기작)은 알 수 없고, 작년과 올해 취향이 다를 수도 있어요(time-varying). "Nobody knows." 그래도 데이터를 최대한 잘 설명하려는 노력이 머신러닝이에요. (0914 00:00–04:04)

함수 모델 vs 확률 모델

📅 0909L01 s7
🧸 쉽게 말하면

과녁에 활을 쏘면 딱 한 점에만 꽂히지 않고 가운데 근처에 흩어져요. 그 흩어짐까지 설명하는 게 확률 모델이에요.

함수 모델은 "x가 60이면 답은 100!"이라고 점 하나로 말하고, 확률 모델은 "100 근처일 가능성이 제일 크고, 멀어질수록 드물어"라고 종 모양으로 말해요.

📐 정식 버전

noisy observation: 많은 데이터는 "진짜 효과(underlying effect) + 노이즈"로 관측된다고 본다.

  • 논리회로 실험: XOR 게이트의 1도 실제로는 5.3V, 6.2V처럼 전압에 노이즈가 낀다. 사진·언어 데이터에도 에러가 있다.
  • 동전 5번: 앞, 앞, 뒤, 뒤, 앞 → "앞면 확률 0.6, 뒷면 0.4구나"라고 판단하는 사고가 확률이다.
  • 노이즈를 어떻게 통계적으로 모델링하느냐에 따라 데이터 패턴의 해석이 달라진다. 그래서 불확실성을 모델에 넣는 확률 모델이 더 합리적이라고 여겨진다.
  • 이때 모델의 파라미터는 확률분포(PDF)의 파라미터다. 예: 가우시안 $\mathcal{N}(\mu, \sigma^2)$ 은 평균 $\mu$ 와 분산 $\sigma^2$, 실수 2개로 정해진다 → "실수 두 개를 최적화하는 문제".

x=60에서 비교 (unseen data $x = 60$ 이 들어왔을 때)

  • 함수(deterministic) 모델: 학습된 직선 $f$ 에 60을 넣어 $\hat{y} = f(60) = 100$ 을 내놓는다. 끝.
  • 확률(probabilistic) 모델: x가 주어졌을 때 y의 conditional PDF를 내놓는다. $$p(y \mid \mathbf{x}) = \mathcal{N}\big(y \mid f(\mathbf{x}), \sigma^2\big)$$ $x = 60$ 이면 평균 $f(60) = 100$, 분산 $\sigma^2$ 인 가우시안이다.

분포에서 답 하나 고르기: conditional PDF 자체가 "순수 베이지안의 결과"다. 여기서 숫자 하나를 고르는 기준(criterion)은 무엇을 중요하게 보느냐에 따라 다르다: MLE(가장 그럴듯한 값), MAP, MMSE(평균제곱오차 최소), Neyman–Pearson criterion 등. MLE와 MAP는 3절에서 정식으로 다룬다.

🎙️ 교수님 한마디

대령 일화: 한 대령이 "산에서 기지국이 꺼지면 통신이 몇 퍼센트 됩니까? 숫자로 얘기해 주세요"라고 했대요. 엔지니어는 답이 "100 근처일 확률이 높고, 많이 크거나 작을 확률은 낮은" 분포라는 걸 알아요. 그래도 단답을 원하면 "그냥 100". 이게 가장 그럴듯한 값을 고르는 MLE의 직관이에요. (0909 56:07)

"구름 잡는 얘기 같아요?" → "맞아요. 아직 안 가르쳐 줬어요." 분포를 어떻게 만드는지는 뒤에서 배워요. (0909 54:48–55:48)

📅 0909 · 0914L01 s8
🧸 쉽게 말하면

요리대회를 떠올려요. 먼저 어떤 요리를 할지 레시피 종류를 고르고, 맛보며 간을 맞추고, 마지막에 심사위원 앞에서 요리해요.

레시피 고르기 = model selection, 간 맞추기 = training, 심사위원 앞 요리 = prediction. 심사위원은 연습 때 한 번도 안 본 사람(unseen data)이에요.

📐 정식 버전

러닝의 목표: "find a model and its corresponding parameters such that the resulting predictor will perform well on unseen data." — such that은 "뒤 문장을 이루도록"이라는 뜻이다. 즉 unseen data에서 잘 동작하는 예측기를 만들기 위해 모델도 정하고 파라미터도 튜닝한다. 새 데이터로 해 보는 것을 test라고 한다.

세 가지 알고리즘 단계 (L01 s8)

  1. prediction / inference: 함수 모델 또는 확률 모델로 새 데이터의 답을 낸다.
  2. training / parameter estimation: 파라미터를 데이터로 추정한다.
    • 비확률적: 예) ERM (Empirical Risk Minimization) → 2절
    • 확률적: 예) ML(Maximum Likelihood), MAP(Maximum A Posteriori) → 3절
    • cross-validation: unseen data 성능을 흉내 내 보는 시뮬레이션
    • regularization / prior: training data와 unseen data 사이에서 모델의 균형을 잡음
  3. model selection: hyperparameter를 고른다.

언제 정하나training data로 학습해서 얻는다학습 전에 정해 두고, 학습 과정을 조절한다
예가중치(weights), bias, 위 식의 3, 5, 6, 0.6learning rate, regularization(정규화) 강도, 다항식 차수, 클러스터 수, 층·뉴런 수

learning vs training: 거의 같은 말로 써도 되지만, 엄밀히 learning은 모델 결정까지 포함하고 training은 정해진 모델의 파라미터 튜닝이다. 요즘은 "학습한다"는 말에 하이퍼파라미터를 건드려 모델 자체를 바꿔 보는 것까지 포함한다 (0914).

파라미터는 어떻게 찾나? 실제 데이터는 수만 개, 찾을 실수는 여러 개다.

  • grid search: 예를 들어 −100부터 +100까지 0.01 간격으로 모든 조합을 다 해 본다. "돈이 많고 시간이 많으면" 제일 확실하지만 너무 느리다.
  • 더 효율적인 방법: gradient descent, least squares(regression) 등 — 뒤에서 배운다.

전체 흐름: 모델 선택 → hyperparameter 결정 → 파라미터 학습 → "문 열어! unseen data 들어와" → test / prediction.
