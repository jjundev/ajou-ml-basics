# ML 실험 화면

상단 모드·테마, 조작 패널, 본문, 설명 패널을 유지한다. 본문은 그래프형 또는 수식 전개형이다. 1024px 미만은 drawer다. 375×812에서도 전체 그래프가 보이도록 fit에 여유를 준다.

- 왼쪽은 변수와 단계, 오른쪽은 수치·범례·공식·오해를 둔다. 조작마다 label·현재 값·min/max/step을 제공하고 빈 숫자나 step 격자 밖의 값은 마지막 유효값으로 되돌린다.
- 분포·회귀·벡터 관계는 평면 정면 시점이 기본이다. 3차원 기하 이해에 도움이 될 때만 회전한다. 시간 진행이 없으면 playback=null이다.
- 눈금·곡선·점·선택 표시는 같은 data→scene 변환을 쓴다. 축 이름·단위와 자동 범위 조정을 안내한다. 공분산 등고선은 축 단위 비율을 같게 유지한다.
- 그래프와 패널은 같은 compute 결과를 읽는다. 단계는 mode와 입력 preset을 함께 바꾼다. 초기화는 같은 seed 표본을 재현한다.
- PAL 역할 색과 범례 이름을 함께 쓰며 두 테마 대비를 확인한다. 밀도 peak·전체 띠가 잘리지 않아야 한다.
- 공식은 로컬 KaTeX, 수치 갱신은 일반 DOM이다. 큰 공식은 명시적 스크롤 영역을 사용할 수 있으나 일반 설명·조작은 가로 넘침이 없어야 한다.
- 해요체로 관찰할 차이를 안내한다. 분산/표준편차·밀도/확률·함수값/관측값을 구분한다. 학습용 데이터·차원 축소를 표시한다.
- 버튼은 44px 이상, 상태는 aria-pressed, 캔버스는 aria-label이다. 색은 토큰/구멍으로만 쓴다. 감소된 움직임 설정을 존중한다.

## 기본 UI

- 본문 제목과 확대·축소·초기화는 `.stage-head` 한 행에 둔다. 긴 제목은 줄바꿈하고 도구는 44px 터치 크기를 유지한다. 도구만을 위한 빈 행이나 장식용 영문 문구·날짜 나열을 만들지 않는다.
- 공통 셸이 앱 안의 모든 스크롤바를 테마 토큰으로 꾸민다. 본문 세로 스크롤과 긴 수식의 가로 스크롤도 같은 스타일을 사용한다. 주제마다 패널 전용 스크롤바 CSS를 복사하지 않는다.
- `.panel-content`의 첫 콘텐츠는 위쪽 구분선·여백·패딩이 없다. 슬롯의 style·ref 요소나 조건부 렌더링 때문에 첫 섹션 처리가 깨지지 않아야 한다. 내용 구분이 필요한 뒤 섹션의 구분선은 유지한다.
- 왼쪽은 입력과 단계, 오른쪽은 계산 결과를 둔다. 입력 label과 필수 모형 조건은 남긴다. 버튼이 이미 알려 주는 사용법, 같은 설명·숫자의 반복, 항상 보이는 장문의 요약은 줄인다. 관찰에 필요한 범례는 계속 보이게 한다.
- 기호·상세 가정·수업 연결 같은 보충 정보는 `<details class="fold"><summary>…</summary>…</details>`에 넣고 기본 닫힘으로 제공한다. 공통 주의사항도 접힌 상태다. 의미 있는 조건과 학습용 단순화를 삭제하지 말고 해당 설명에 둔다.

## 수식 전개형

`view:'formula'`는 장면 계약의 수식 단계를 사용한다. 한 줄씩 누적하고 이전 식을 남기며 현재 단계의 이유만 펼친다. 단계 목록에는 제목만 표시해 본문 설명과 중복하지 않는다. 비교식은 넓은 화면에서 두 열, 좁은 본문에서는 한 열이다.

확대·축소는 수식 글자 크기(기본 1, 0.8~1.6배)를 바꾼다. 초기화는 크기만 1배로 돌리고 단계와 입력은 보존한다. 이전/다음은 양 끝에서 비활성화하고, 포커스된 수식 본문의 좌우 방향키도 같은 순서로 이동한다. 모드 변경은 출발식과 기본 크기로 돌아간다. 그래프형 확대는 기존 카메라 배율에 적용한다.

PC 1440×900·모바일 375×812, 두 테마, 모든 모드에서 제목/도구 정렬, 패널 첫 구분선, 가로·세로 스크롤, 긴 식 확대, 단계 이동과 drawer/Escape를 확인한다. 수식 오류와 페이지 전체 가로 넘침이 없어야 한다.

## 브라우저 도구

주제 QA와 템플릿 검증은 Playwright와 Chrome을 쓴다. 일반 `require('playwright')`, `npm root -g`, 홈 `.cache` 아래의 `node_modules/playwright` 순서로 찾고, 찾은 경로는 `ML_PLAYWRIGHT_MODULE` 환경변수로만 넘긴다. RUN과 evidence의 스크립트도 `require(process.env.ML_PLAYWRIGHT_MODULE||'playwright')`로 불러오며 절대 경로를 적지 않는다. Playwright가 없으면 사용할 수 있는 다른 실제 브라우저 도구로 같은 항목을 확인하고, 그것도 없으면 화면 검증 보류로 보고한다.

## 템플릿 수정 시 검증

스킬 루트에서 `node --test tests/*.test.cjs`로 검사한다. 실제 브라우저 검증은 `node tests/ui.browser.cjs`이며 위 브라우저 도구를 사용한다. 이 검증은 OS 임시 폴더에서만 그래프·수식 예시를 빌드하고 PC/모바일·두 테마의 캡처와 results.json 경로를 반환한다. 캡처를 직접 확인하고 기존 공개 자료를 재생성하지 않는다.
