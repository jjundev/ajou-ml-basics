# 머신러닝기초 영상 정리 노트

영상 링크 하나로 **다운로드 → Gemini 전사 → 화면 직접 읽기 → 정리 노트**를 만든다. 원본은 `.claude/skills/ml-video-note`, `.agents/skills/ml-video-note`는 상대 심볼릭 링크다.

## 입력

`/ml-video-note <URL> [MMDD]`

- `URL`: 영상 링크 (yt-dlp가 지원하는 사이트)
- `MMDD` (선택): 노트를 넣을 복습노트 날짜. 생략하면 스크립트가 고른다.

## 필요한 것

- `yt-dlp`, `ffmpeg`/`ffprobe`, `pdftotext`, `uv` (Python은 표준 라이브러리만 사용)
- 저장소 `.env`의 `GOOGLE_API_KEY` (Vertex AI API 키). AI Studio 엔드포인트(`generativelanguage.googleapis.com`)는 이 키로 403이므로 쓰지 않는다.
- 이미지 파일을 열어 볼 수 있는 도구 (화면 읽기용)

## 경로 규칙

| 산출물 | 위치 |
|---|---|
| 원본 영상 | `~/Downloads/<제목> [<id>].mp4` (보관, 지우지 않음) |
| 작업 파일 | `$TMPDIR/ml-video-note/<id>/` (`meta.json`, `audio/`, `transcript/`, `sheets/`) |
| 원문 전사 | `STT/<slug>.md` |
| 정리 노트 | `복습노트/<MMDD>/.pack/영상정리_<slug>/영상정리_<slug>.md` |
| 노트 그림 | 같은 폴더의 `figures/NN_<장면>.png` |

- `STT/<MMDD> 머러기.md`(수업 녹음 전사)와 이미 있는 `.pack` 파일은 **절대 덮어쓰거나 고치지 않는다**. `.pack` 안에는 `영상정리_<slug>/` 폴더만 새로 만든다.
- 복습노트 날짜 폴더를 **새로 만들지 않는다**.

## 워크플로

`S=.claude/skills/ml-video-note/scripts`, 저장소 루트에서 실행한다. API 호출은 반드시 스크립트로 한다. 셸에서 `"$m:generateContent"`처럼 쓰면 zsh가 `:g`를 수식어로 해석해 모든 모델이 거짓 404를 낸다.

### 1. 다운로드·오디오 분할

```bash
uv run python $S/fetch.py "<URL>"
```

마지막 줄의 `meta.json` 경로를 이후 단계에 쓴다 (`M=...`). 이미 받은 영상이 `~/Downloads`에 있으면 다시 받지 않는다.

### 2. 전사 (Gemini API)

```bash
uv run python $S/transcribe.py "$M" --repo . --hints "<영상 주제 용어 10~20개, 쉼표 구분>"
```

- 기본 모델은 `gemini-3.5-flash`이고, 404·빈 응답이면 `gemini-3.1-pro-preview` → `gemini-2.5-flash` 순으로 넘어간다. 실제 사용한 모델이 전사본 머리에 적힌다.
- `--hints`에는 영상 제목과 관련 강의노트에서 뽑은 전문용어를 넣는다.
- 종료 코드 1은 일부 파트 실패를 뜻한다. 그 파트만 다시 돌리려면 `--model gemini-3.1-pro-preview`로 재실행한다. 그래도 실패하면 노트에 빈 구간을 명시한다.
- 401/403이면 키 문제이므로 멈추고 사용자에게 `.env`를 확인해 달라고 한다.
- 429(사용량 한도)는 30·60·90초 쉬었다가 같은 모델로 다시 시도하고, 그래도 안 되면 다음 모델로 넘어간다. 파트 시작은 5초씩 엇갈린다. 429로 대체 모델이 자주 쓰이면 `--workers 1`로 다시 돌린다.

### 3. 저장 날짜 고르기

```bash
uv run python $S/pick_date.py "$M" --repo . [--date MMDD]
```

- 판단 순서: ① 인자로 준 날짜 → ② 강의노트 PDF에서 영상 id를 찾아 그 쪽의 슬라이드 날짜 → ③ 영상·전사 키워드와 각 날짜 정리노트의 겹침 점수
- 종료 코드 2면 확정하지 못한 것이다. 출력된 `candidates`와 `evidence`를 사용자에게 보여 주고 `MMDD`를 지정해 달라고 한 뒤 **멈춘다**.
- 성공하면 `pack_dir`과 `evidence`를 노트 머리의 "위치" 줄에 쓴다.

### 4. 화면 직접 읽기

```bash
uv run python $S/sheets.py sheets "$M"
```

- 프레임을 일정 간격(기본 6초, 긴 영상은 시트가 40장 이하가 되도록 자동으로 늘림)으로 뽑아 3x3 시트로 묶는다. 각 칸의 시각은 `sheets/sheets.json`에 있다 (행 우선, 왼→오, 위→아래).
- **모든 시트를 순서대로 이미지 도구로 직접 열어 본다.** 화면 읽기를 외부 API에 맡기지 않는다.
- 시트마다 다음을 기록해 장면 로그를 만든다.
  - 슬라이드 제목, 화면 글자, 수식 (그대로 옮김)
  - 그림 요소: 점, 색, 곡선, 화살표, 표, 수치
  - 이전 칸과 달라진 점
- 장면 로그와 전사본을 시각으로 맞춰서, 화면에 없는 설명(예시 수치, 주의 사항)은 전사본에서 보강한다.

### 5. 핵심 장면 그림

```bash
uv run python $S/sheets.py frame "$M" --at 93,144,... --names 01_hard_vs_soft,02_...,... --out "<pack_dir>/figures"
```

- 노트의 섹션마다 6~10장을 고른다. 시각은 `sheets.json`의 칸 시각을 쓰고, 애니메이션 중간이면 ±3초 조정한다.
- **뽑은 그림을 하나씩 열어서** 의도한 장면인지 확인한다. 틀리면 시각을 바꿔 다시 뽑는다.

### 6. 정리 노트 작성

`<pack_dir>/영상정리_<slug>.md`를 한국어로 쓴다. 구조:

1. `# <영상 제목 한국어/원어> — <채널> 영상 정리`
2. 메타 목록
   - 영상 (링크, 길이)
   - 위치 (`pick_date` evidence)
   - 정리 방식: "프레임 N장을 직접 보고 전사본 `STT/<slug>.md`와 맞춰 정리, 타임스탬프는 간격 단위 근삿값"
   - 전사 모델
3. `> 한 줄 요약` 인용 블록
4. 시간순 섹션 `## n. <주제> (MM:SS–MM:SS)`
   - 화면에 요소가 하나씩 쌓이는 장면은 `| 시각 | 화면 | 내용 |` 표로 쓴다.
   - 섹션마다 핵심 그림 `![설명](figures/NN_...png)`과 **화면 설명 → 핵심** 순서로 쓴다.
   - 화면 글자와 수식은 그대로 옮기고 수식은 `$…$` / `$$…$$`로 쓴다. 영상 표현이 부정확하면(예: "거리"라고 말했지만 실제로는 높이) 그 점을 짚는다.
5. `## 수업 내용과 연결하기`
   - `| 영상 표현 | 수업 용어 | 수식 |` 표. 그날 `정리노트_<MMDD>_*.md`의 기호와 용어에 맞춘다.
   - **영상에서 빠진 것**(수업에서 보충되는 가정·증명·일반화)을 번호 목록으로 쓴다.
6. 광고·구독 안내 구간은 한 줄로만 적는다.

### 7. 점검과 보고

- 수식과 용어를 그날 정리노트와 대조한다.
  - 정의 없이 쓴 기호가 없는지
  - 정규화 상수, 차원, 첨자가 맞는지
  - "영상에 없는 내용"을 영상 내용처럼 쓰지 않았는지
- 완료 보고에 다음을 적는다.
  - 노트·전사본·그림 경로
  - 고른 날짜와 근거
  - 사용 모델
  - 실패하거나 확인하지 못한 구간
- 커밋하지 않는다.

## 완료 기준

- [ ] `STT/<slug>.md`가 영상 끝까지 전사되었다 (실패 파트는 표시).
- [ ] 저장 날짜를 근거와 함께 골랐거나, 고르지 못해 사용자에게 물었다.
- [ ] 모든 프레임 시트를 직접 열어 보았다.
- [ ] 그림을 하나씩 열어 장면이 맞는지 확인했다.
- [ ] 노트가 `복습노트/<MMDD>/.pack/영상정리_<slug>/`에만 생겼고 기존 파일은 그대로다 (`git status`로 확인).
