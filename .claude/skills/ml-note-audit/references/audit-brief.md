# 감사 지시문

---
머신러닝기초 복습자료의 설명 결함을 감사한다. 파일은 수정하지 않는다.

- 대상: <대상>
- 형제 자료: <형제 자료> — 대상과 기호·번호·상수·주장을 대조하는 데만 쓴다. 형제 자료 자체의 결함은 대상과 충돌할 때만 보고한다.
- HTML은 본문 문장과 수식만 본다. 인터렉티브는 설명 문구·STEPS 수식·패널 문장만 보고 JS/CSS는 무시한다.

찾을 범주(이것만):
1. **정의 없는 기호**: 수식에 처음 나온 기호의 뜻이 그 전에 없다. 앞에서 정의한 기호가 다른 뜻으로 바뀌었는데 다시 정의하지 않았다(예: U가 직선에서 M차원 부분공간으로).
2. **압축된 유도**: 한 줄에 대입·전개·분배·스칼라 이동·전치·결합법칙으로 묶기·역행렬 곱하기 중 둘 이상이 숨어 있어, 왼쪽에서 오른쪽으로 가는 과정을 독자가 재현할 수 없다.
3. **어긋난 근거**: 단계에 적힌 이유가 실제로 그 등식을 성립시키는 이유가 아니다(예: 실제로는 "λ*가 스칼라라 자리를 바꾸고 결합법칙으로 묶는다"인데 "분모가 스칼라이므로"라고 씀). 근거가 결론을 뒷받침하지 않는 문장도 포함한다.
4. **수학 오류·조건 누락**: 식·부호·차원·주장이 틀렸다. 조건이 필요한 주장을 항상 성립하는 것처럼 썼다(절댓값, 대칭, 대각화 가능, 열 독립, 중근 등).
5. **자료 간 불일치**: 같은 대상을 다른 기호로 쓰거나 같은 기호를 다른 대상에 쓴다(S의 정의, λ₁이 최대인지 최소인지, 데이터 차원 값). 한 자료의 주장이 다른 자료와 반대다.
6. **바로잡은 주장의 재사용**: 자료가 다른 곳에서 틀렸다고 바로잡은 설명을 다시 근거로 쓴다.

보고하지 않는 것: 문체·어휘 취향, 짧지만 맞고 따라갈 수 있는 서술, 숫자 정답의 재확인 결과(틀렸을 때만 범주 4로 보고).

규칙:
- 각 항목은 원문을 짧게 그대로 인용한다. 인용할 수 없으면 보고하지 않는다.
- 범주 4는 직접 다시 계산했을 때만 confidence high로 쓴다.
- 독자가 어디서 막히거나 잘못 배우는지 구체적으로 쓰고, 고칠 내용을 한두 문장으로 제안한다.
- 약한 항목 여럿보다 확실한 항목 몇 개를 낸다.

심각도:
- Critical: 범주 4, 범주 5·6 중 학생이 틀린 내용을 배우게 되는 것.
- Important: 범주 1·2·3, 나머지 범주 5·6.
- Minor: 이해를 막지는 않지만 한 문장으로 고칠 수 있는 것.

출력 형식(이것만):
```
## Critical
- [파일:줄] (범주 n, confidence high|medium) "인용" — 문제 → 고칠 내용
## Important
- …
## Minor
- …
```
없으면 각 절에 "없음".
