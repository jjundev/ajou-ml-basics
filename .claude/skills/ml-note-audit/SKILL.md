# 머신러닝기초 설명 감사

복습자료의 설명이 학생이 따라갈 수 있고 맞는지 감사한다. 숫자 정답·구조·렌더링 검사는 다른 단계가 맡는다. 이 감사는 **서술과 유도**만 본다.

**읽기 전용**: 감사는 파일을 고치지 않는다. 결과는 보고만 하고, 수정은 호출한 생성 절차의 작성자나 사용자가 한다.

## 단독 실행: `/ml-note-audit <MMDD|MMDD-MMDD>`

1. `복습노트/<날짜>/`마다 대상 목록을 만든다: 날짜 폴더의 `정리노트_*`, `복습문제_*`, `문제설명_*`, `인터렉티브_*` HTML과 `.pack/`의 같은 이름 MD. MD가 있으면 MD를 주로 읽고, 줄 번호는 HTML에서 찾게 한다.
2. 날짜마다 감사 에이전트 둘을 띄운다(모두 병렬). 브리프는 [감사 지시문](references/audit-brief.md)이다. 모델은 기본 모델을 쓰고 낮추지 않는다.
   - A: `<대상>` = 정리노트, `<형제 자료>` = 같은 날짜의 나머지 자료.
   - B: `<대상>` = 복습문제·문제설명·인터렉티브, `<형제 자료>` = 정리노트.
   - 한쪽 묶음이 비면 그 에이전트는 띄우지 않는다. 두 결과에서 같은 결함은 하나로 합친다.
3. 결과를 받으면 Critical 항목은 원문을 직접 열어 인용이 실제로 있는지 확인한다. 확인하지 못한 항목은 그렇게 표시한다.
4. 날짜별로 Critical / Important / Minor를 합쳐 보고한다. 파일은 수정하지 않는다.

## 생성 절차에서 부를 때

호출하는 스킬이 다음을 채워 감사 에이전트를 띄운다. `<대상>`에 정리노트와 다른 종류의 자료가 함께 있으면 단독 실행의 A·B처럼 둘로 나누고, 아니면 하나만 띄운다. lite에서도 생략하지 않고 모델을 낮추지 않는다.

- `<대상>`: 이번에 만든 자료(stage 경로).
- `<형제 자료>`: 같은 날짜 공개 폴더에 이미 있는 다른 종류의 자료. 없으면 `없음`.
- 결과는 호출 스킬의 RUN에 `audit.md`로 저장한다.
- Critical과 Important는 담당 작성자에게 모아서 한 번 되돌린다. 남은 항목은 호출 스킬 보고의 "미해결"에 적는다. 감사 결과만으로 배포를 막지 않는다.
- 에이전트 호출이 실패하면 생성을 멈추지 않고 보고에 `설명 감사 누락: <원인>`을 적는다.

보고 줄 형식: `설명 감사: Critical n / Important n / 미해결 n (RUN/audit.md)`
