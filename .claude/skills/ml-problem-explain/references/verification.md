# 검토 기록과 발행

기계 검사는 구역·소문항·수식 보존·자원·파일 해시를 검사해요. 의미와 답이 맞다는 판단은 하지 않아요. build가 만든 `review.json`은 전부 `not_run`이에요. 실제 확인을 수행한 에이전트만 기록을 갱신해요. 과제 원 PDF 또는 MML의 문항 페이지와 대조하고, 원 답안을 독립 검산의 결과로 간주하지 않아요.

JSON의 `input_hash`는 현재 원본과 설명 조각에 묶여요. build 출력의 `artifact_hashes`도 그대로 검토 대상이에요. 조각·원본·렌더링 파일을 바꿨다면 다시 build하고 검토해요. 예전 검토 보고서는 통과하지 않아요.

미분 문항 검토자는 `../../ml-review-pack/references/vector-derivative-convention.md` 전체를 필수로 읽어요. content/independent 근거에 변수 차원·미분 결과 차원·곱 순서·0으로 놓기·양변 전치·원문 보존 또는 수정 요청 근거를 남겨요. 원문이 명시한 열 관례를 보존하는 것은 수학적 충돌 자체가 아니며, 방향 미지정 문항은 강의의 행 관례를 사용해요. 본문뿐 아니라 sum·용어·MD·저장 조각까지 대조하고 행 관례 저작 대상에 공통 검사기를 실행해요. 해설만 고친 뒤 원 문제나 PDF도 고쳤다고 보고하지 않아요. 관례를 바꿨다면 기존 pass·해시를 복사하지 않고 실제 재검토해요.

- `source_visual`: 문항 조건·그림·소문항을 PDF/MML의 실제 페이지와 대조. reviewer와 evidence에 자료/페이지/대조 결과.
- `content`. 모든 문항·소문항을 기록해요. 새 조각의 제목 순서와 유형별 풀이 형식을 확인해요. 문제의 단서와 방법 선택, 실제 첫 단계, 필요한 조건과 중간식만으로 풀이가 재현되는지 읽어 봐요. 반복 설명·대안 풀이·재검산은 덜고, 필수 연결이 빠졌으면 최소 문장이나 식을 보완해요. 최종 답에 모든 결과와 단위·조건이 들어 있고 핵심 풀이 바로 뒤, 답 확인 바로 앞에서 읽히는지 대조해요. 답 확인은 원조건이나 논증을 직접 점검하고, 우측 요약 및 동반 Markdown과 본문의 답·조건이 일치해야 해요.
- `independent`: 같은 모든 items, method=`exact|symbolic|numerical|proof|qualitative`, conclusion과 evidence. 검산 스크립트·출력·자료 위치를 구체적으로 기록.
- `browser`: 1280×900 및 375×812, light/dark. 모든 문항의 목차·이전/다음·요약·수식·표·그림·링크를 확인. 콘솔·KaTeX 오류·누락 자원·문서 가로 넘침은 0. `<table>` 및 표 컨테이너(`.table-wrap`)의 모바일(375px) 가로 넘침 0. `ol.deriv` 행별 수식 1개 + 보이는 한 줄 주석(~25자)의 정렬 및 가로 넘침 0(화면이 좁을 때 `deriv-fit` 스크립트가 주석을 식 아래로 올바르게 재배치하는지 점검). 짧은 인라인 수식의 스크롤 컨테이너와 수식 영역의 보이는 스크롤바는 0. 구역 24px·제목 아래 12px·소문항 16px 간격, 행렬 잘림과 겹침을 실제 렌더링으로 확인. 긴 수식은 의미 단위 줄바꿈을 우선하고, 더 나눌 수 없는 긴 수식만 안내와 함께 스크롤바 없는 국소 이동을 허용. 외부 요청 없이 로컬 자원으로 렌더링.

각 단계와 items는 status=`pass`, 비어 있지 않은 reviewer/evidence여야 발행돼요. `not_run`, `fail`, `disputed`는 발행을 보류해요. numerical은 유한한 tolerance>0, 0<=residual<=tolerance도 필요해요. proof에 숫자 예제 확인만 있는 evidence는 수동 검토에서 승인하면 안 돼요.

```json
{
  "status": "pass",
  "reviewer": "검증을 수행한 에이전트",
  "evidence": "evidence/transpose.py 및 transpose-result.txt: 입력 행렬과 일치",
  "method": "exact",
  "conclusion": "전치 후 다시 전치하면 원 행렬과 정확히 같음"
}
```

사용한 근거 파일은 대상 작업 디렉터리의 `evidence/` 아래 보관해요. `references`에는 읽은 저장소 내부 자료의 절대 path와 SHA-256을 기록해요. 발행 직전 재확인돼요. `artifact_hashes`에는 manifest를 포함한 현재 stage 파일의 상대경로→SHA-256을 기록해요. build가 넣은 값을 승인 전 점검하며 임의로 오래된 검토에 새 해시만 덮어씌우지 않아요.

답 충돌·조건 모호함·원문 미확인은 해당 팩을 disputed로 표시하고 이유를 보고해요. 다른 독립 팩은 통과하면 발행할 수 있어요. 기존 파일은 변경하지 않고 설명 소유 파일만 백업 후 교체하며 실패 시 복구해요.


## 현재 기준과 재렌더링 검토 계약

현재 `review_policy_version`은 `problem-explain-2026-10-20-row-derivatives`다. 새 review.json·manifest의 버전이 일치해야 발행된다. 구버전/버전 없는 검토를 단순히 현재 버전으로 바꾸거나 pass를 복사하지 않는다. 기준 변경은 실제 content·independent 재검토를 요구한다.

content는 문제의 단서·적용 조건·기호 대응·유형별 풀이 형식, 소문항별 답과 검산, 오답 판별 기준과 우측 요약의 일치를 확인한다. 부정형의 참·거짓과 선택 적합성, 표현 결함과 공식 답 확인 여부는 구역 간에 일관되게 반영한다. 과목별 disputed 규칙을 적용한다. 독립 검산은 작성자와 다른 검산자가 정답·참고 풀이·설명 조각을 보지 않고 문제·그림·필요한 이론 자료만으로 먼저 수행한다. 컨트롤러가 그 결과를 참고 답과 대조한다.

rerender의 검토 재사용은 동일한 입력·조각·입력 그림과 무결한 발행 자료, 검증된 모든 참조, 같은 검토 기준을 전제로 한다. 참조가 없거나 바뀌면 content·independent도 not_run으로 두고 다시 검토한다. 전자회로2는 problems.txt가 같더라도 문제 MD·그림이 바뀌면 재사용하지 않는다. source_visual·browser는 매번 새 stage에서 수행한다. 구조 검사는 내용 검증이 아니다.

browser는 1280×900·1024×900·375×812, light/dark에서 실제 확인한다. 1023→1024 경계에서 목차·문제 기본 열림, 저장한 닫힘 유지, 원문 탭(원문 없는 문항은 숨김), 문제 패널 왼쪽·오른쪽 붙이기·띄우기, 이동·크기 조절·화면 내 제한, 모바일 접힘, 그림 확대와 인쇄 문제/원문 보존을 확인한다. ol.deriv와 table-wrap 표의 375px 가로 넘침 0과 deriv-fit 리플로우를 확인한다. 유효한 객관식은 오답·정답·다시 풀기·판정 이동, 모델 없는 문항은 정적 표시를 확인한다. 코드 문자·들여쓰기·수식·소문항·원문을 보존하고 외부 요청·콘솔/KaTeX 오류·누락 자원·문서 가로 넘침은 0이어야 한다.

새 저작분은 본문에서 최종 답이 핵심 풀이 뒤와 답 확인 앞에 표시되는지, 다시 풀기 제목·목록과 보존 안내 푸터가 없는지 확인한다. 요약을 열어 용어가 맨 아래 한 번 나타나는지, 다른 문항으로 이동하면 해당 용어만 표시되는지 확인한다. 같은 문항의 문제 패널에서는 옮긴 용어 탭이 숨겨져야 한다. 저장 조각의 표지와 MD의 최종 답·용어도 대조한다.

참조 HTML·MD·SVG가 로컬 그림을 사용하면 해당 그림도 references에 절대 경로와 SHA-256으로 별도 기록한다. 참조 그림 해시 누락·변경은 검토 재사용과 새 발행을 막는다. 옮긴 그림의 이전 바이트를 확인할 수 없으면 현재 파일을 자기 자신과 비교해 같은 그림이라고 간주하지 않는다.

## 패널 동작 회귀

임시 stage의 실제 생성 결과를 빈 로컬 HTTP 포트로 제공하여 1280×900 / 375×812, light / dark에서 확인한다. 서로 다른 두 토픽을 이동하면 중앙 h3는 보이고 우측에는 같은 제목이 없어야 한다. `#sum-for.sums`는 하나이며 현재 `.sum:not([hidden])`만 정확한 요약을 표시한다. 표지에는 기존 안내, 문제 카드에는 힌트·풀이와 푼 문제 토글을 확인한다. 문제설명은 문제·원문 탭, 이전/다음, 수식 제목과 긴 수식도 확인한다. 이동·새로고침 전후 read/solved의 실제 키와 ID 배열 payload를 비교하고 콘솔·KaTeX 오류가 0인지 확인한다. 기존 missing-sum 검사가 여전히 누락을 잡아야 한다. 서버·브라우저는 finally에서 종료한다. 고정 PDF 템플릿·인쇄 CSS는 변경하지 않는다.

## 본문과 우측 패널 표시 계약

중앙 주제·문항 제목과 패널의 고정 제목은 유지한다. 우측에는 중앙 제목을 복사하지 않는다. `sum-for`는 제목이 아닌 유일한 `.sums` 컨테이너 ID로 보존한다. `.sum` 전환, 문제·원문 탭, 힌트·풀이, 앵커, read/solved 저장 키와 payload를 유지한다. 예습·과제·시험도 같은 표시 계약을 따른다.

요약은 같은 토픽 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축한다. 식·용어·항목 수에 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않으며 보충의 범위·출처·불확실성을 보존한다. 문제설명은 풀이의 판단 조건·결론·단서를 압축하고 문제 데이터와 풀이 본문을 바꾸지 않는다.

검토 시 자료·토픽별로 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 기록하고 본문 주장, 대응 요약 문장, pass/unresolved와 생략 이유를 대조한다. 보완 후 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고도 동기화하되 원래 없는 MD 형식은 만들지 않는다. 요약·예고·링크 화면의 기존 구조를 유지한다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. 실제 검사 뒤에만 status를 바꾸며 HTML·감사표 해시 변경 후에는 기록을 갱신해야 한다.
