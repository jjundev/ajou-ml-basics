# 문제설명 저작

수업에서 개념을 배운 학생이 주어진 문제의 풀이를 재현할 만큼만 써요. [공통 설명 깊이](../../ml-review-pack/references/problem-solving-depth.md)와 MML·교안·기존 정리노트의 관련 범위를 먼저 확인해요. STT는 필요한 경우 보조로 사용하고 수업 밖 보충은 표시해요.

- 풀이에 실제로 쓰는 방법 하나를 끝까지 보여 줘요. 문제의 단서, 필요한 적용 조건과 기호 대응, 실제 첫 식, 핵심 중간 단계, 답을 확인할 근거를 남겨요.
- 문장이나 식을 하나씩 가리고 “이걸 빼면 이 문제에서 무엇을 새로 추측해야 하나?”라고 확인해요. 앞에서 나온 근거, 배운 개념의 재설명, 대안 풀이, 반복 산술과 재검산은 덜어내요. 여러 소문항에 공통인 근거는 한 번만 써요.
- 익숙한 계산은 결과로 압축해도 돼요. 유도·증명 자체가 질문이라면 결론을 성립시키는 중간식과 논리 연결을 남겨요. 그림을 읽는 문제는 실제 그림의 단서와 판정 기준을 적어요. 모든 문항에 공통 줄 수를 적용하지 않아요.

미분 문항은 저작 전에 `../../ml-review-pack/references/vector-derivative-convention.md` 전체를 필수로 읽어요. 방향 미지정 문제의 스칼라 미분은 행벡터로 쓰고, 0으로 놓은 뒤 양변 전치로 열 정규방정식을 얻는 단계를 보여 줘요. 기존 원문이 열 gradient를 명시하면 조건을 유지하고 해당 관례로 설명하며 understand와 sum에서 강의와의 차이를 밝혀요. 사용자에게 문제 조건 변경까지 요청받았을 때만 그 범위의 원천·조건·PDF를 함께 갱신해요. recall/start/solve/verify/pitfall/sum·용어·MD·저장 조각 사이에서 방향을 섞지 않아요. 변수의 열벡터 방향과 출력×입력 Jacobian은 유지해요.

각 조각의 직계 구역은 아래 순서로 작성해요. 최종 답은 solve의 마지막 자식으로 붙이는 별도 제목 구역이에요.

| 구역 | 표시 제목 | 내용 |
|---|---|---|
| understand | 풀이 목표 | 문제의 기호로 구할 것을 적고, 결정적인 조건만 짚어요. |
| recall | 풀이 단서 | 문제의 단서가 실제 방법·식으로 어떻게 이어지는지 적어요. |
| start | 첫 단계 | 값을 넣은 첫 식, 표의 뼈대, 또는 그림에서 볼 지점을 보여 줘요. |
| solve | 핵심 풀이 | 결론에 도달하는 핵심 계산·유도·판단을 적어요. |
| solve 안의 final-answer | 최종 답 | 원 질문 순서대로 결과, 단위, 필요한 조건을 바로 읽게 적어요. |
| verify | 답 확인 | 답을 원조건에 대입하거나 성립 조건을 직접 확인해요. |
| pitfall | 주의할 점 | 답을 바꾸는 이 문항의 대표 혼동을 짧게 짚어요. |

새 조각은 understand에 `layer eli5`, pitfall에 `layer warn`, 나머지 직계 구역에 `layer formal`을 사용해요. pitfall에 `data-omit-retry=""`를 붙이고, 본문 retry 구역은 생략해요. 객관식 위젯의 다시 풀기 동작은 정답 모델 계약을 따라요. 저장된 옛 조각을 그대로 재조립하는 경우에는 기존 형식을 사용해요.

**풀이 단서**에는 방법 선택을 바꾸는 조건과 이번 문제에 필요한 기호만 연결해요. 공식이 없는 문제는 판단 기준이나 논증 조건만 써도 돼요. **첫 단계** 뒤에 순서 안내가 필요한 경우 한 줄로 붙여요. **핵심 풀이**의 각 소문항은 필요한 근거로 곧장 시작해요. 답의 형태를 먼저 알면 전개가 쉬워지는 경우에만 형태를 짧게 밝혀요.

1. **수치 반복 계산형**(숫자·항이 3개 이상 이어지는 경우):
   줄글 문단에 수치를 나열하지 말고 `<div class="table-wrap"><table>...</table></div>` 표로 계산 단계를 분리해요. **대표 1항 대입 예시 1줄** + **전체 표** + **결과 해석 1줄** 구성을 지켜요.
2. **유도·증명형**(등호 연쇄·논리 근거가 핵심인 경우):
   `<div class="deriv-body"><ol class="deriv"><li><div class="deriv-eq">$$...$$</div><div class="deriv-why"><p>...</p></div></li>...</ol></div>` 형식을 사용해요.
   - **줄 하나 = 식 하나**: `.deriv-eq`에는 디스플레이 수식(`$$...$$`)이 정확히 1개예요.
   - **주석은 늘 보인다**: `.deriv-why`의 첫 `<p>`는 비울 수 없고, 그 줄에서 한 연산이나 쓴 성질을 한 줄(약 25자)로 밝혀요.
   - **`<details>` 절대 금지**: `ol.deriv` 내부에서도 접힘/펼치기(`<details>`, "자세히")는 계약 위반이에요.
   - **마지막 식**: 유도가 다음 단계나 최종 결론으로 넘기는 식은 `li.deriv-gen`으로 강조할 수 있어요.
3. **짧은 단답·개념 판별형**:
   불필요한 표나 `ol.deriv`를 억지로 쓰지 않고 2~3줄 핵심 근거만 간결히 적어요.

검증은 작성자가 독립적으로 수행하되 독자용 verify에 새 숫자 문제·역행렬·오답 행렬 계산을 강제로 덧붙이지 않아요. 일반 증명은 조건·곱 순서·비영벡터 근거를 점검하고 수치 예로 대체하지 않아요. 이미 충분한 검토를 다른 방법으로 다시 증명할 필요는 없어요. pitfall도 그 문항의 결정적 혼동을 짚으면 되며, 틀린 경로 전체를 계산할 의무는 없어요.

`source.json`의 subparts가 a,b이면 **solve와 verify 모두** 각각 아래 표지를 한 번씩 사용해요. 단일 문항도 `main` 표지가 필요해요. 소문항 제목에 `(a)`, `(b)`를 한 번 표시하고, 같은 묶음의 문단 앞에는 같은 표지를 반복하지 않아요. `(a)에서 구한 결과`처럼 의미 있는 참조는 유지해요. 조립기도 제목이 있는 solve/verify 묶음의 같은 접두사와 뒤 공백만 제거해요.


```html
<div class="layer formal" data-explanation="solve">
  <h4>핵심 풀이</h4>
  <div data-subpart="a">
    <h4>(a) 새 기저 좌표</h4>
    <p>$\lambda_1+\lambda_2=5$와 $-\lambda_1+\lambda_2=1$을 더하면 $\lambda_2=3$, 첫 식에 넣으면 $\lambda_1=2$예요.</p>
  </div>
  <div data-subpart="b">
    <h4>(b) 정규화 판정</h4>
    <p>두 기저 벡터의 길이 제곱은 각각 $1^2+1^2=2$예요.</p>
  </div>
  <section class="final-answer">
    <h4>최종 답</h4>
    <p>(a) 새 기저 좌표는 $[2,3]^\top$이에요.</p>
    <p>(b) 두 기저 벡터 모두 정규화되어 있지 않아요.</p>
  </section>
</div>
<div class="layer formal" data-explanation="verify">
  <h4>답 확인</h4>
  <div data-subpart="a"><h4>(a) 검산</h4><p>$2\mathbf b_1+3\mathbf b_2=[5,1]^\top=\mathbf x$예요.</p></div>
  <div data-subpart="b"><h4>(b) 확인</h4><p>각 벡터에 절댓값이 1인 성분이 두 개라 길이가 1을 넘어요.</p></div>
</div>
```

행렬은 차원·곱 순서, 확률은 조건·정규화, 미분은 대상·상수·가정을 필요한 곳에 설명해요. `~해요` 체와 영어 전문용어 병기를 사용해요. 기존 원문·조건·질문·그림은 조립기가 붙이므로 재작성하지 않아요. 과제의 영어 원문 전문도 유지돼요.

마지막에 직계 `<div class="sum" hidden>` 하나를 넣어 시작·핵심 판단·검산을 요약해요. 템플릿은 이 요약으로 현재 문항의 핵심을 표시하고 맨 아래에 해당 용어를 붙여요. 본문 hidden/details, 인라인 style, 실행 코드와 on* 속성은 사용할 수 없어요. 수식은 `$...$`/`$$...$$`, 그림은 저장소 내부 파일 상대경로나 정적인 inline SVG를 사용해요. 소문항 표지를 임의로 합치지 않아요.

개념 링크는 실제 존재하는 정리노트의 문항/토픽 anchor만 연결해요. 조각의 상대 링크와 그림은 입력 카드 HTML의 디렉터리 기준이에요. 소문항별 증명과 정성 문항은 적용 조건과 논증을 확인하며, 몇 개 숫자 예제로 증명이 끝났다고 쓰지 않아요.

## 수식과 여백

짧은 수식은 문장 안에 두고 수식마다 스크롤 컨테이너를 만들지 않아요. 여러 행렬 답은 각각 독립된 줄에 배치해요. 긴 유도는 의미가 유지되는 등호·항을 기준으로 여러 식으로 나눠요. 한 수식의 여러 줄이 필요하면 `aligned`를 사용하고 수식 내용을 생략하지 않아요. 원문은 다시 쓰지 않고 템플릿의 표시 규칙으로 배치해요.

### 식 줄(ol.deriv)과 강조
- **줄 하나 = 식 하나**: `.deriv-eq`에는 디스플레이 수식(`$$...$$`)이 정확히 1개예요. 같은 연산의 두 식(예: $\mathbf{p}_i^\top\mathbf{p}_i=1$, $\mathbf{p}_i^\top\mathbf{p}_j=0$)은 `\qquad`로 한 줄에 둘 수 있어요.
- **주석은 늘 보인다**: `.deriv-why`의 첫 `<p>`는 비울 수 없고, 그 줄에서 한 연산이나 쓴 성질을 한 줄(약 25자)로 밝혀요. 접어 숨기는 `<details>`는 금지예요.
- **등호 정렬**: 같은 좌변을 잇는 식 줄은 `\hphantom{좌변}=`으로 시작해 `=` 위치를 맞춰요.
- **강조**: `\textcolor{#3182f6}{...}`는 `.deriv` 안에서만, 바로 윗줄과 달라진 부분(대입한 항, 바뀐 인자)에만 한 줄에 1~2곳 써요. 토픽에서 처음 강조를 쓰는 경우 상단에 `<p class="deriv-legend">파란색은 이전 줄에서 바뀐 항이에요.</p>`를 둘 수 있어요. 색은 CSS가 테마별로 전환하므로 다른 색 코드를 직접 쓰지 않아요.
- **간격**: CSS가 정하므로(`deriv-body`, `ol.deriv` 사이 24px, 줄 사이 8px, 식 줄 안쪽 12px) 인라인 `style`이나 빈 문단으로 간격을 조절하지 않아요.
- **긴 식 리플로우**: 주석 칸 옆에 다 들어가지 않는 긴 식은 템플릿의 `deriv-fit` 스크립트가 주석을 식 아래로 내려요. 375px 모바일에서도 한 줄로 너무 길면 식을 둘로 나누거나 정의 부분을 주석으로 옮겨요.

### 표(table)와 table-wrap
수치 반복 계산에 사용하는 모든 `<table>`은 반드시 `<div class="table-wrap"><table>...</table></div>`로 감싸요. 모바일 375px 화면에서도 표 내부에서만 가로 스크롤이 발생하고 본문 전체가 화면 밖으로 밀려나 넘치는 현상(가로 스크롤 넘침)이 없어야 해요.

요약은 `<div class="summary-group"><h4>첫 줄</h4><p>...</p></div>`처럼 의미별로 묶어요. 제목과 내용 사이는 12px, 요약 그룹과 설명 구역 사이는 24px, 소문항 사이는 16px인 템플릿 규칙을 사용해요. 간격을 만들려고 빈 문단이나 연속 br을 넣지 않아요. 페이지 하단에 보존 안내 문구를 붙이지 않아요. 화면을 바꾸거나 요약 너비를 조절한 뒤에도 수식이 읽혀야 해요.


## 우측 요약의 용어와 문제 패널의 출제 근거

조각 끝에 직계 `<section data-problem-panel="terms" data-summary-terms=""><h4>용어</h4><dl class="terms">…</dl></section>`을 하나 작성해요. 이 속성으로 템플릿이 용어를 해당 문항의 우측 요약 맨 아래로 옮겨요. 실제 풀이에 쓰는 용어만 한국어·영어 이름과 이번 문제에서의 뜻으로 짧게 정리해요. 기호·차원·조건은 필요한 경우에 덧붙여요.

출제 근거 패널(`data-problem-panel="provenance"`)은 원천 자료에서 확인한 근거(교과서 Example/Exercise 번호·쪽, 교안 슬라이드, 수업 날짜)가 있을 때만 작성해요. 확인한 근거가 없으면 패널을 만들지 않아요. 비어 있는 패널은 탭 자체가 숨겨져요.

## 용어·보기·문항 결함의 일관성

recall은 원천에서 확인한 이름과 개념을 짧게 대응하고, pitfall은 인접 오답과의 결정적 차이를 설명한다. 비교 대상·단위·조건·결과를 분명히 한다. 자료에 없는 동의어·번역·가정을 원문에 끼워 넣지 않는다. 긴 설명을 start·solve·pitfall에 복제하지 않는다.

객관식은 understand에서 긍정/부정 질문 방향과 단일/복수 선택 조건을 밝힌다. solve에서는 보기마다 근거를 판정하고, 진술의 참·거짓과 질문에 대한 선택 적합성을 구별한다. ‘항상’ 같은 절대 표현만으로 오답으로 정하지 않는다. ㄱㄴㄷ형은 개별 진술을 판정한 뒤 조합을 고른다. 선택지 목록을 소문항으로 바꾸지 않는다.

표현 결함·필요 가정·출제 의도상 답과 엄밀한 답의 차이는 understand·solve에 밝히고, verify의 소거·검산과 pitfall·sum에도 같은 조건과 유보를 유지한다. 공식 답 미확인이면 그 사실을 밝힌다. 공식 답 부재만으로 독립 검산 성공/실패를 추정하지 않는다. 정상 문항에는 불필요한 모호성 문구를 붙이지 않는다. 이 원칙은 과목별 기존 disputed 정책을 완화하지 않는다. DS의 UB·비종료·은행 충돌, ML의 미해결 수학적 모호함, EC2의 workbook 풀이와 독립 검산 불일치는 계속 발행을 보류한다. 원자료를 몰래 수정하지 않는다.

해설·답을 본 뒤의 성공을 독립 회상이나 학생 숙달 확인으로 보고하지 않는다. 객관식 정답 모델은 입력의 검증된 데이터만 사용하며 해설에서 새로 추정하지 않는다.

## 본문과 우측 패널 표시 계약

중앙 주제·문항 제목과 패널의 고정 제목은 유지한다. 우측에는 중앙 제목을 복사하지 않는다. `sum-for`는 제목이 아닌 유일한 `.sums` 컨테이너 ID로 보존한다. `.sum` 전환, 문제·원문 탭, 힌트·풀이, 앵커, read/solved 저장 키와 payload를 유지한다. 예습·과제·시험도 같은 표시 계약을 따른다.

요약은 같은 토픽 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축한다. 식·용어·항목 수에 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않으며 보충의 범위·출처·불확실성을 보존한다. 문제설명은 풀이의 판단 조건·결론·단서를 압축하고 문제 데이터와 풀이 본문을 바꾸지 않는다.

검토 시 자료·토픽별로 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 기록하고 본문 주장, 대응 요약 문장, pass/unresolved와 생략 이유를 대조한다. 보완 후 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고도 동기화하되 원래 없는 MD 형식은 만들지 않는다. 요약·예고·링크 화면의 기존 구조를 유지한다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. 실제 검사 뒤에만 status를 바꾸며 HTML·감사표 해시 변경 후에는 기록을 갱신해야 한다.
