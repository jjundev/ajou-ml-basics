# 문제풀이 입문 설명 저작

이론을 읽었지만 문제풀이 경험이 부족한 학생에게 실제 첫 줄부터 완성 답과 검산까지 설명해요. 기존 카드의 풀이를 길게 바꾸는 것으로 끝내지 말고, 왜 그 첫 줄과 계산 방법을 선택하는지 밝혀요. MML·교안·기존 정리노트의 관련 페이지를 먼저 확인해요. STT는 필요한 경우 보조로 사용하고 수업 밖 보충은 표시해요.

각 `explanations/pN.html`은 다음 직계 구역을 각각 하나 포함해요. 본문 답은 모두 펼쳐요.

| data-explanation | 작성할 내용 |
|---|---|
| understand | 주어진 조건과 구할 것을 내 말로 읽어요. `layer eli5` |
| recall | 문제의 단서 → 개념의 뜻 → 공식과 기호 → 적용 조건과 선택 이유. `layer formal` |
| start | 종이에 쓸 실제 첫 식·문장·표의 첫 행, 필요한 개념 |
| solve | 한 줄에 한 식, 변형 이유·성질·적용 가정. `layer formal` |
| verify | 완성 답과 실제 대입·독립 계산·특수 경우 등 검산 |
| pitfall | 이 문항에서 하기 쉬운 오류. `layer warn` |
| retry | 설명을 닫고 수행할 1~3개 체크리스트 |

표 순서대로 일곱 구역을 작성해요. recall의 제목은 **이 문제를 봤을 때 떠올릴 개념과 공식**이에요. 개념 이름이나 공식만 나열하지 말고, 문제의 어떤 표현·조건이 그 개념을 떠올리게 하는지부터 설명해요. 영어 전문용어, 각 기호의 뜻, 공식이 성립하는 조건과 이 문제에 적용하는 이유를 입문형으로 연결해요. recall은 일반 개념을 고르는 과정이고 start는 주어진 값·기호로 종이에 적는 실제 첫 줄이에요. 긴 설명을 두 구역에 복제하지 않아요.

```html
<div class="layer formal" data-explanation="recall">
  <h4>이 문제를 봤을 때 떠올릴 개념과 공식</h4>
  <p>‘전치’라는 말에서 전치(transpose), 즉 행과 열의 교환을 떠올려요.</p>
  <p>$(A^\top)_{ij}=A_{ji}$예요. $i$는 행, $j$는 열 번호이고, $m\times n$ 행렬의 전치는 $n\times m$이에요.</p>
  <p>직사각형 행렬과 열벡터에도 적용돼요. 원소의 값과 부호는 그대로 두고 위치만 바꿔요.</p>
</div>
```

공통 개념은 한 번 설명하고, 서로 다른 개념을 요구하는 소문항은 (a), (b)처럼 구분해요. 개념 수를 고정하지 않아요. 공식이 필요 없는 정성·증명 문항에서는 정의·판단 기준과 논증 조건을 설명해요. 우측 sum에 `summary-group`을 추가해 `<h4>떠올릴 개념·공식</h4>` 아래 핵심 개념·공식을 짧게 적어요. 본문 전체를 요약에 복제하지 않아요.

`source.json`의 subparts가 a,b이면 **solve와 verify 모두** 각각 아래 표지를 한 번씩 사용해요. 단일 문항도 `main` 표지가 필요해요. 소문항 제목에 `(a)`, `(b)`를 한 번 표시하고, 같은 묶음의 문단 앞에는 같은 표지를 반복하지 않아요. `(a)에서 구한 결과`처럼 의미 있는 참조는 유지해요. 조립기도 제목이 있는 solve/verify 묶음의 같은 접두사와 뒤 공백만 제거해요.

```html
<div class="layer formal" data-explanation="solve">
  <h4>왜 이렇게 푸는지 함께 따라가요</h4>
  <div data-subpart="a"><h4>(a)</h4><p>실제 식, 변형 이유, 완성 답을 써요.</p></div>
  <div data-subpart="b"><h4>(b)</h4><p>실제 식, 변형 이유, 완성 답을 써요.</p></div>
</div>
<div class="layer formal" data-explanation="verify">
  <h4>완성 답과 검산</h4>
  <div data-subpart="a"><h4>(a) 검산</h4><p>계산을 별도로 확인한 결과를 써요.</p></div>
  <div data-subpart="b"><h4>(b) 검산</h4><p>조건에 대입한 결과를 써요.</p></div>
</div>
```

행렬은 차원·곱 순서, 확률은 조건·정규화, 미분은 대상·상수·가정을 필요한 곳에 설명해요. `~해요` 체와 영어 전문용어 병기를 사용해요. 기존 원문·조건·질문·그림은 조립기가 붙이므로 재작성하지 않아요. 과제의 영어 원문 전문도 유지돼요.

마지막에 직계 `<div class="sum" hidden>` 하나를 넣어 시작·핵심 판단·검산을 요약해요. 이 요약만 UI의 우측으로 이동해요. 본문 hidden/details, 인라인 style, 실행 코드와 on* 속성은 사용할 수 없어요. 수식은 `$...$`/`$$...$$`, 그림은 저장소 내부 파일 상대경로나 정적인 inline SVG를 사용해요. 소문항 표지를 임의로 합치지 않아요.

개념 링크는 실제 존재하는 정리노트의 문항/토픽 anchor만 연결해요. 조각의 상대 링크와 그림은 입력 카드 HTML의 디렉터리 기준이에요. 소문항별 증명과 정성 문항은 적용 조건과 논증을 확인하며, 몇 개 숫자 예제로 증명이 끝났다고 쓰지 않아요.

## 수식과 여백

짧은 수식은 문장 안에 두고 수식마다 스크롤 컨테이너를 만들지 않아요. 여러 행렬 답은 각각 독립된 줄에 배치해요. 긴 유도는 의미가 유지되는 등호·항을 기준으로 여러 식으로 나눠요. 한 수식의 여러 줄이 필요하면 `aligned`를 사용하고 수식 내용을 생략하지 않아요. 원문은 다시 쓰지 않고 템플릿의 표시 규칙으로 배치해요.

요약은 `<div class="summary-group"><h4>첫 줄</h4><p>...</p></div>`처럼 의미별로 묶어요. 제목과 내용 사이는 12px, 요약 그룹과 설명 구역 사이는 24px, 소문항 사이는 16px인 템플릿 규칙을 사용해요. 간격을 만들려고 빈 문단이나 연속 br을 넣지 않아요. 화면을 바꾸거나 요약 너비를 조절한 뒤에도 수식이 읽혀야 해요.


## 용어·보기·문항 결함의 일관성

recall은 원천에서 확인한 이름과 개념을 짧게 대응하고, pitfall은 인접 오답과의 결정적 차이를 설명한다. 비교 대상·단위·조건·결과를 분명히 한다. 자료에 없는 동의어·번역·가정을 원문에 끼워 넣지 않는다. 긴 설명을 start·solve·pitfall에 복제하지 않는다.

객관식은 understand에서 긍정/부정 질문 방향과 단일/복수 선택 조건을 밝힌다. solve에서는 보기마다 근거를 판정하고, 진술의 참·거짓과 질문에 대한 선택 적합성을 구별한다. ‘항상’ 같은 절대 표현만으로 오답으로 정하지 않는다. ㄱㄴㄷ형은 개별 진술을 판정한 뒤 조합을 고른다. 선택지 목록을 소문항으로 바꾸지 않는다.

표현 결함·필요 가정·출제 의도상 답과 엄밀한 답의 차이는 understand·solve에 밝히고, verify의 소거·검산과 pitfall·sum에도 같은 조건과 유보를 유지한다. 공식 답 미확인이면 그 사실을 밝힌다. 공식 답 부재만으로 독립 검산 성공/실패를 추정하지 않는다. 정상 문항에는 불필요한 모호성 문구를 붙이지 않는다. 이 원칙은 과목별 기존 disputed 정책을 완화하지 않는다. DS의 UB·비종료·은행 충돌, ML의 미해결 수학적 모호함, EC2의 workbook 풀이와 독립 검산 불일치는 계속 발행을 보류한다. 원자료를 몰래 수정하지 않는다.

해설·답을 본 뒤의 성공을 독립 회상이나 학생 숙달 확인으로 보고하지 않는다. retry는 해설을 닫고 개념·첫 줄을 다시 떠올리게 한다. 객관식 정답 모델은 입력의 검증된 데이터만 사용하며 해설에서 새로 추정하지 않는다.

## 본문과 우측 패널 표시 계약

중앙 주제·문항 제목과 패널의 고정 제목은 유지한다. 우측에는 중앙 제목을 복사하지 않는다. `sum-for`는 제목이 아닌 유일한 `.sums` 컨테이너 ID로 보존한다. `.sum` 전환, 문제·원문 탭, 힌트·풀이, 앵커, read/solved 저장 키와 payload를 유지한다. 예습·과제·시험도 같은 표시 계약을 따른다.

요약은 같은 토픽 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축한다. 식·용어·항목 수에 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않으며 보충의 범위·출처·불확실성을 보존한다. 문제설명은 풀이의 판단 조건·결론·단서를 압축하고 문제 데이터와 풀이 본문을 바꾸지 않는다.

검토 시 자료·토픽별로 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 기록하고 본문 주장, 대응 요약 문장, pass/unresolved와 생략 이유를 대조한다. 보완 후 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고도 동기화하되 원래 없는 MD 형식은 만들지 않는다. 요약·예고·링크 화면의 기존 구조를 유지한다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. 실제 검사 뒤에만 status를 바꾸며 HTML·감사표 해시 변경 후에는 기록을 갱신해야 한다.
