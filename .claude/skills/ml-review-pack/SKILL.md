# 머신러닝기초 복습팩

수업 녹음 전사(STT)와 강의자료, MML 교과서로 한 기간의 복습팩을 만든다. 중간에 사용자에게 묻지 않고 끝에 한 번 보고한다. 커밋은 제안만 한다.

**설명 깊이 기준**: 메인·작성자·리뷰어·감사자는 [문제풀이에 필요한 설명 깊이](references/problem-solving-depth.md)를 전체 읽는다. 목표는 “문제를 푸는 데 지장이 없을 정도로만”이다. 신규 생성·기존 설명 수정 모두 필요한 판단·기호·조건·계산 연결을 갖추고, 반복·주변 지식은 선별한다. 기존 RUN 브리프와 audit.md에 핵심 유지·축약 판단을 기록하고 모든 작성·감사 브리프에 이 경로와 적용 토픽을 전달한다.

**학습자 설명 기준**: 신규 생성·기존 설명 수정 모두 시작할 때 메인은 [학습자 설명 기준](references/learner-reasoning-patterns.md)을 전체 읽는다. 대상의 구성·역할, 익숙한 개념과의 대응, 목적과 선택 제약을 연결하는 기준이다. 적용 토픽과 필요한 연결을 기존 `RUN/learning-map.json` 브리프에 적고 정리노트 작성자·리뷰어에게 필수 읽기로 전달한다. 수업 범위의 근거로 쓰거나 이해 반응을 숙달로 기록하지 않는다. 파일 누락은 일반 규칙으로 진행하고 참고 누락을 보고한다.

**이야기 흐름 기준**: 신규 생성·기존 설명 수정 모두 메인·정리노트 작성자·리뷰어는 [이야기 흐름으로 본문 쓰기](references/narrative-flow.md)를 전체 읽는다. 섹션마다 검산한 주 예시를 이어 쓴다. 방법의 한계나 결과의 차이가 개념·수식·선택 기준을 설명하는 핵심 토픽은 비교를 먼저 보여 주고 관찰값을 다음 식에 대입한다.

**벡터 미분 필수 규칙**: 미분이 포함된 새 저작·기존 자료 수정에서는 메인·정리노트 작성자·문제 작성자·리뷰어 모두 [벡터 미분 관례](references/vector-derivative-convention.md)를 전체 읽는다. 변수는 열벡터, 스칼라 목적함수의 미분은 행벡터로 쓰고 열 정규방정식으로 옮길 때 양변 전치를 보인다. 문제 조건·힌트·풀이·상세 해설·요약·용어·생성 원본·MD·PDF에 함께 적용한다. 기존 원문의 명시적 다른 관례는 이 레퍼런스의 원문 보존 분기로 처리한다.

**산출물** (`복습노트/<range>/`, 수업 날짜마다 폴더 하나):
날짜 폴더 바로 아래에 `정리노트_<range>_<slug>.html`, `문제설명_<range>_<slug>.html`, **`복습문제_<range>_<slug>-문제.pdf`와 `-답안.pdf`**를 둔다. 신규 팩은 같은 폴더에 `확인문제_<range>_<slug>.html`도 생성한다. `.pack/`에는 Markdown 세 개, `복습문제_<range>_<slug>.cards.json`, `figures_<range>/`와 문제설명 소유 자료를 둔다. 작업용 복습문제 HTML은 RUN에서 조립·검증·렌더링한다. HTML의 PDF 링크에는 파일명만, `.pack/` 안의 Markdown에서 날짜 폴더의 HTML과 PDF를 링크할 때는 `../`를 쓴다. 문제지와 해설지는 동봉된 전자회로2 고정 템플릿으로 16:9 PDF를 만든다.

**인자**: `[MMDD | MMDD-MMDD]`

**진행 표시**: 단계마다 한 줄만 쓴다. 예: `3/9 작성 중: 섹션 5개 + 카드 10개 (병렬)`

**경로 약속**
- `SKILL` = 이 파일이 있는 폴더(`.claude/skills/ml-review-pack`)의 절대 경로
- `REPO` = 저장소 루트
- `RUN` = `<scratchpad>/review-pack/<range>/`
- 셸 상태는 Bash 호출 사이에 이어지지 않는다. 아래 명령의 `$SKILL`, `$RUN`, `$REPO`는 실행할 때마다 실제 절대 경로로 바꿔 쓰거나, 같은 명령 앞에 `SKILL=… RUN=… REPO=…`를 붙여 설정한다. `cd`는 쓰지 않고 파일도 절대 경로로 넘긴다.

## 정리노트 본문 서식
긴 계산·유도는 [단계형 본문 기준](references/staged-body.md)을 작성자·리뷰어가 읽고 적용한다. 단계 안의 유도는 같은 파일의 **식 줄 + 주석**(`ol.deriv`) 서식으로 쓴다. 기존 자료의 서식 변경도 같은 기준을 사용하되 요청한 토픽의 HTML·대응 MD만 갱신한다. 좌우 패널, 기존 도입, 읽음 상태와 링크를 보존한다.

## 기존 정리노트 설명만 개선하는 경우
사용자가 큰 그림·개념 연결·기호 설명 등 기존 정리노트의 설명 개선을 요청하면 이 경로를 쓴다. 복습문제·답안 PDF·문제설명·영상의 내용이 바뀌지 않으면 전체 복습팩을 재생성하지 않는다.
1. `references/big-picture-first.md`, `references/learner-reasoning-patterns.md`, `references/problem-solving-depth.md`, `references/narrative-flow.md`를 전체 읽고 대상 HTML·MD·기존 첫 토픽·연결을 확인한다. 이번 풀이에 필요한 연결과 편집 판단을 RUN의 저작 브리프에 기록한다. 관찰이 필요한 토픽에는 고정할 대상·바꿀 값 또는 방법·볼 차이·그 결과를 받는 첫 식을 적고 기존 위젯 재사용 여부를 판단한다. 기존 ID·위젯·PDF·인터랙티브 링크와 필요한 수식의 의미·조건을 보존한다. 사용자가 내용 축약을 요청한 경우 불필요한 설명·수식은 선별 삭제하고 독립적 보충은 선택 읽기로 둘 수 있다. 레이아웃만 바꿀 때는 원문·수식을 보존한다.
2. 원자료와 기존 설명을 대조해 도입·유도 연결을 작성한다. `big-picture-first.md`의 전체 연결·출발식·변경점·단계별 연산·결과 재사용·복원 요약을 필요한 개념 묶음에 적용한다. 일반 공식의 실제 대입과 수업 관례를 보이고 수업 공식·동치 재표현·보충을 구분한다. 대상 HTML과 모든 대응 MD를 RUN에 백업하고 stage에서 수정한다. 큰 그림이 이미 있으면 중복 토픽 대신 기존 도입을 보강한다.
3. `python3 SKILL/scripts/check_learning_map.py <정리노트 HTML...>`와 `check_html.py`를 실행한다. 녹음 위치와 편집 경위 금지는 `references/content-rules.md`에 따라 본문·인용·요약·그림 설명·각주·footer 및 대응 MD에 적용한다. MD의 새 설명·수식·링크가 HTML과 대응하는지 확인한다. 도입과 수정한 유도를 실제로 읽고, 적용 토픽의 관찰에서 첫 식까지 HTML·MD 양쪽으로 따라간다. 설명 감사에도 학습자 기준, 이야기 흐름 기준, 적용 토픽 브리프를 전달한다. `big-picture-first.md`의 핵심 전환 기준으로 충분한 구간까지 본문 근거·검토자가 보충한 연결을 대조하고 `RUN/audit.md`에 남긴다.
4. 375px·데스크톱, 두 테마에서 도입의 실제 가시성·수식·줄바꿈·목차·화면 이동·기존 링크를 확인한다. 수정한 위젯은 `references/browser-check.md`의 대표 설정을 비교한다. 검증된 HTML·MD를 함께 반영하고, 실패하면 해당 노트는 기존 파일을 보존한다.
5. 변경 날짜, 설명의 차이, 검사 결과, 백업·RUN과 미해결을 보고한다. PDF와 문제의 재검증을 이번 설명 수정의 검증인 것처럼 보고하지 않는다.

## 절차

### 0. 준비
1. `REPO`에 `STT/`, `강의노트/`, `교과서/Mathematics_for_Machine_Learning.pdf`가 모두 있는지 확인한다. 하나라도 없으면 "머신러닝기초 저장소에서만 동작합니다"라고 알리고 멈춘다.
   형제 `ml-problem-explain/SKILL.md`와 형제 설명 스킬의 실행기 `mpe_cli.py`도 시작 전에 확인한다. 없으면 경로와 원인을 보고하고 시작하지 않는다.
2. STT 목록은 NFC로 읽는다. macOS에는 NFD 파일명이 섞여 있다.
   ```bash
   python3 -c "import os,unicodedata as u,re;n=[u.normalize('NFC',f) for f in os.listdir('$REPO/STT')];print(sorted(m.group(1) for f in n if f.endswith('머러기.md') and (m:=re.match(r'(\d{4})',f))))"
   ```
3. 기간을 정한다.
   - 인자가 있으면 그 기간을 쓴다.
   - 인자가 없으면 `복습노트/*/정리노트_<range>_*.html`(예전 형식인 `복습노트/정리노트_*`도 포함) 중 가장 늦은 끝 날짜를 찾고, 그 뒤의 STT를 모두 쓴다. `정리노트_*`가 하나도 없으면 STT 전부를 쓴다.
   - 해당 STT가 하나도 없으면 사용 가능한 날짜를 보여 주고 멈춘다.
   - `range`는 첫 STT 날짜 하나이거나 `첫-끝` 형식이다.
   - 해당 범위에 기존 정리노트 HTML, 복습문제 원고 또는 예전 복습문제 HTML이 있으면 기존 팩 갱신으로 기록한다. 날짜 폴더와 예전 복습노트 루트 형식을 모두 확인한다. 기존 기본 팩 산출물이 없으면 신규 팩이다. 확인문제 파일만 있을 때도 신규 팩으로 진행한다.
4. 실행 폴더를 만든다. 서브에이전트에게는 `RUN`, `RUN/repo`, `SKILL` 경로만 넘긴다.
   ```bash
   mkdir -p "$RUN"/{summaries,sections,cards,work} && ln -sfn "$REPO" "$RUN/repo"
   ```
   에이전트는 `RUN` 밖에 쓰지 않는다. 임시·보조 파일(그림 생성 스크립트, 초안, 복사본)은 `RUN/work/`에만 둔다. 저장소(`STT/`, `강의노트/`, `교과서/`)에는 아무도 쓰지 않고, `복습노트/`에는 메인 에이전트만 쓴다.

### 1. 범위 파악
1. **먼저** 관련 `강의노트/Lecture*.pdf` 텍스트를 슬라이드 번호와 함께 `RUN/slides.txt`에 추출한다(PyMuPDF, 쪽마다 `=== LXX sN ===`, 몇 초면 끝난다). 요약 에이전트는 이 파일이 있다고 보고 시작하므로 추출이 끝난 뒤에 띄운다.
   - 관련 PDF: 이전 팩(`복습노트/*/정리노트_*`)이 끝까지 다루지 않은 Lecture PDF 전부. 확실하지 않으면 넉넉히 넣는다.
   - 추출에 실패하면 STT만으로 진행하고 보고서에 적는다(브리프의 `slides.txt` 줄은 "없음"으로 바꿔 넘긴다).
2. 그다음 STT 날짜마다 요약 에이전트 1명을 **병렬로** 띄운다. 브리프는 `references/stt-summary-prompt.md`에 있다.
   - `<LectureXX_*.pdf>`: 그 날짜가 다룬 슬라이드가 들어 있는 PDF(`slides.txt`와 이전 팩의 범위로 판단). 확실하지 않으면 1의 관련 PDF를 모두 적는다.
   - `<YYYY-MM-DD>`: 연도는 이번 학기 연도(오늘 날짜 기준), 월·일은 `<MMDD>`.
3. 에이전트가 도는 동안 메인 에이전트는 MML에서 관련 장과 Example·연습문제 위치를 찾는다(`references/problem-selection.md`의 스니펫).
4. 요약이 끝나면 **학습 레퍼런스 적용 여부**를 정한다. 요약·슬라이드에서 이번에 "다룸/일부"인 토픽에 벡터/교차 공분산, 공분산 행렬, 또는 확률벡터의 선형·아핀 변환에 따른 공분산 계산이 있으면 메인은 `references/scalar-to-vector-covariance.md`를 **전체 읽는다**. 키워드가 예고·안 다룸에만 있거나, 선형변환이 공분산과 무관하면 적용하지 않는다.
   - 이 파일은 학습자 배경과 설명 전략이다. 수업 범위·식·교수님 발언의 근거는 STT·강의자료·MML로 유지한다. 설명됨을 숙달로, 미확인을 지식 부족으로 판정하지 않는다.
   - 관련 토픽과 사용할 설명 연결·미확인 지점을 정하고, 2단계 manifest에서 확정한 토픽 id로 3단계의 해당 섹션 작성자와 6단계 리뷰어 브리프에 전달한다. 파일이 없거나 읽을 수 없으면 일반 규칙으로 진행하고 9단계에 참고 누락을 보고한다.

### 2. manifest
#### 2a. 문항 선별 판정
- 메인은 1단계의 슬라이드 대조표와 용어·식 목록으로 수업 범위와 토픽 ID 초안을 정한다. 수업 범위와 `references/problem-selection.md`에 따라 후보를 선별한다. MML 예제는 PDF 원문 상자의 조건·수식을 확인하고, 연습문제는 해당 풀이에 필요한 개념이 수업 범위 안인지 확인한다. 이전 팩의 출처와 대조해 중복을 제외한다. 갱신 대상 팩은 중복 대조에서 제외하며, 그 팩의 기존 문항도 출처와 수업 범위를 다시 확인한다.
- 후보별 원문과 PDF 쪽, 수업 범위 근거, 선정·제외 이유를 `RUN/problem-pages.txt`에 기록한다. 명세표가 있으면 선정 문항의 태그를 `RUN/blueprint.json`에 기록한다. 허용된 명세표 보충 자작 문항은 사용 토픽·보충 목표·개수 제한을 확인하고 독립 검산을 통과한 것만 적격으로 센다. 자작 문항을 난이도 비율 보정에 쓰지 않는다.
- 적격 후보가 12개를 넘으면 출제 기준에 맞는 8~12문항을 먼저 선정한다. 적격 문항이 8개 미만이면 `RUN/problem-pages.txt`에 적격 수, 8개까지 부족한 수와 근거, `WITHHELD`를 남긴다. 명세표 검사기가 `gaps`를 허용해도 이 판정은 같다. 기획을 호출하거나 기획 파일을 조회하지 않고 9단계 보류를 보고해 기획 없이 종료한다.
- 8~12문항에 명세표 기준을 적용한다. 난이도 비율만 미달하면 실제 분포와 목표, 후보 탐색·제외 근거를 `RUN/problem-pages.txt`에 남기고 `RUN/blueprint.json`의 `gaps.levels`에 사유를 기록한다. 이 경우 기획은 진행하고 발행은 별도로 판단한다. 그 밖의 명세표 미달은 기존 보충·부족 사유 규칙으로 처리한다. 명세표가 없으면 기존 근사 난이도 기준을 적용하고 명세표 미사용과 부족한 이유를 `RUN/problem-pages.txt`에 기록한다.
- 필요한 근거를 갖추면 선정 문항·토픽 ID와 `PASS`를 `RUN/problem-pages.txt`에 남기고 2b에 넘긴다.

#### 2b. 기획과 작성 준비
- `PASS` 후 기획 담당 1명에게 `RUN`, 선정 문항, manifest 토픽 ID와 범위, STT 요약·슬라이드·기존 노트·관련 MML 쪽을 경로로 전달한다. `references/problem-solving-depth.md`, `references/learner-reasoning-patterns.md`, `references/big-picture-first.md`, `references/narrative-flow.md`를 전문으로 읽게 한다. 적용 범위가 있는 공분산·벡터 미분 기준도 전문을 읽는다. 이해 반응과 독립 숙달은 별도로 판정한다. 호출 때 작업자 ID를 보관한다.
- 기획 담당은 `RUN/learning-map.json`의 기존 저작 브리프에 오늘의 질문, 대상의 구성·역할, 익숙한 연결, 목적·선택 제약·조건, 구할 결과와 유도 목적을 근거 토픽·자료 위치에 맞춰 기록한다. 핵심 전환에는 출발식·도착식, 예상 질문과 필요한 연결, 기존 결과의 재사용·일반식 대입, 미분 관례·보충 경계와 풀이에 필요한 최소 깊이를 적는다. 첫 학습 토픽의 큰 그림을 먼저 확정한다. 섹션별 주 예시·수치를 적고, `narrative-flow.md` 규칙 2가 적용되는 토픽에는 고정할 대상·바꿀 값 또는 방법·볼 차이·그 결과를 받는 첫 식을 같은 브리프에 적는다. 검산 스크립트와 결과는 `RUN/work/`에 둔다. 기존 manifest 스키마와 HTML 계약을 사용한다.
- 기획 담당은 브리프 경로, 핵심 질문, 적용 토픽 ID, 출처·범위 쟁점과 참고 누락을 짧게 반환한다. 읽을 수 없는 참고는 누락·원인을 기록하고 일반 작성 규칙을 적용한다.
- 메인은 기획과 독립인 작업을 묶어서 한다. `references/big-picture-first.md`를 전체 읽어 큰 그림의 검증 기준을 확인한다. `RUN/answers.py`(`fractions`)로 정답을 검산하고, 슬라이드 대조표·용어 목록과 `references/manifest-guide.md`에 따라 `RUN/manifest.json`의 선정 문항·토픽·범위를 정리한다.
- 독립 작업 뒤에는 보관한 ID의 완료 신호를 받거나 그 ID로 차단 대기한다. 전체 알림만 지원하면 해당 작업자의 완료를 골라 확인한다. 다른 작업자의 알림으로 기획 파일을 조회하지 않는다. **파일 폴링 금지.** 타임아웃·실패면 해당 작업자의 상태·실패 근거를 확인해 대기를 이어가거나 복구한다. 위임을 끝내 마칠 수 없으면 해당 작업자의 쓰기가 종료된 뒤 기획 필수 읽기·브리프·예시 검산을 메인 직접 수행으로 완료한다. 부분 파일은 완료 근거가 될 수 없다.
- **완료 후 한 번에 검증**한다. 짧은 요약과 현재 실행의 `RUN/learning-map.json`을 최종 manifest의 범위·선정 문항·토픽 ID 및 첫 학습 토픽과 대조하고, `RUN/work/`의 섹션별 예시 검산 근거를 같은 묶음에서 확인한다. 출처·범위 쟁점은 판단에 필요한 자료 구간을 확인한다.
- 범위·출처·선정 문항·토픽 ID가 달라지면 2a 재판정부터 한다. `WITHHELD`가 되면 보류를 보고하고 종료한다. `PASS`면 최신 입력으로 manifest·정답·해당 명세표를 맞추고 기획 담당에게 브리프를 갱신하게 한다. 갱신도 작업자 완료 뒤 한 번에 대조한다.
- **3단계 진입 조건**은 최신 입력의 2a `PASS`, 기획 브리프 대조 완료와 `python3 "$SKILL/scripts/manifest.py" "$RUN/manifest.json"`의 `OK`다. 명세표가 있으면 `scripts/check_blueprint.py`도 `OK`여야 한다(자작 문항은 `--self-checks "$RUN/self-checks.json"` 추가). 정답 검산은 최종 선정 문항과 일치해야 한다.

### 3. 작성
- 2b의 진입 조건을 모두 확인한 뒤 작성자를 호출한다.
- 모든 정리노트 작성자는 `references/learner-reasoning-patterns.md`를 전체 필수 읽기로 받고 해당 토픽의 학습자 연결 브리프를 적용한다. 공분산 레퍼런스의 `적용 없음`은 이 일반 학습자 기준을 생략한다는 뜻이 아니다.
- 모든 정리노트 작성자에게 큰 그림 브리프와 `references/big-picture-first.md`를 전달한다. 첫 토픽 작성자는 도입을 작성하고, 다른 작성자는 자기 유도의 목적과 처음 등장하는 기호를 설명한다. 관련 본문은 기억할 출발식에서 변경점·한 단계 연산·다음 결과의 대입까지 연결하고 짧은 복원 요약으로 마친다. 수업 공식과 재표현을 구별하며 같은 설명을 반복하지 않는다.
- 작성자는 `big-picture-first.md`의 핵심 전환 기준에 따라 기존 `RUN/learning-map.json` 저작 브리프에 출발식·도착식, 독자의 예상 질문과 필요한 연결을 기록한다. 작성·리뷰·감사의 실제 전개 대조는 같은 기준을 쓰며 새 manifest 필드나 필수 HTML 속성은 추가하지 않는다.
- 모든 정리노트 작성자에게 `references/narrative-flow.md`와 그 섹션의 주 예시·관찰 비교 브리프를 전달한다. 적용 토픽의 작성자는 브리프의 비교를 수식 설명 앞에 놓고 같은 숫자를 첫 식에 재사용한다. 끝나면 같은 파일의 자기 검사를 수행한다.
- 섹션마다 작성자 1명을 띄운다. 브리프는 `references/content-rules.md`, 위젯 규칙은 `references/widget-rules.md`에 있다.
- 문제 작성자 1명이 모든 카드를 쓴다. 브리프는 `references/card-rules.md`에 있다. 미분 문항이면 `references/vector-derivative-convention.md`도 필수 읽기로 전달하고 변수/미분 차원·전치 단계·원문 관례 처리·동기화 대상 목록을 작성 결과에 포함시킨다.
- 모두 **한 메시지에서 병렬로** 띄운다. 모델은 Claude에서 opus, GPT에서 sol을 쓴다.
- 브리프의 `<…>` 자리는 실제 경로, id, 금지어 목록(`<forbidden 목록>`), 예고 토픽 id(`<preview_topic>`), 섹션 작성자에게 필요한 MML 쪽 번호(`<쪽>`, 1단계 3에서 찾은 PDF 쪽), 그리고 섹션 작성자에게는 manifest `links` 중 그 섹션 토픽에 속한 것만(`<이 섹션의 links 목록>`) 채워 넣는다.
- 섹션 작성자 브리프의 `<학습 레퍼런스>`는 관련 토픽이 있는 섹션에만 `필수 읽기: <SKILL>/references/scalar-to-vector-covariance.md 전체; 적용 토픽: <id 목록>; 설명 연결: <가중합/성분 계산/정의/차원 중 필요한 것>; 미확인 지점: <이번 섹션에서 확인할 것>`으로 채운다. 무관한 섹션에는 `적용 없음`, 파일을 읽지 못한 관련 섹션에는 `참고 누락: <원인>; 일반 작성 규칙 적용`으로 채운다. 레퍼런스 예제를 근거 없이 새 문제 카드로 추가하지 않는다.
- 위젯은 팩 전체에 0~2개다. **메인 에이전트가 작성자를 띄우기 전에** `references/widget-rules.md`에 따라 배정한다. 배정한 섹션의 `<위젯>` 자리에 "토픽 `<토픽 id>`에 위젯 1개: <고정할 대상과 움직일 값, 관찰할 결과>"를 적는다. 나머지 작성자에게는 "위젯 없음"을 전달한다. 비교가 필요한 토픽은 정적 그림이나 표로도 설명할 수 있다. 정한 토픽과 이유는 보고서 "스킬이 정한 사항"에 적는다.

### 4. 조립
- `review_pdf_stage.py`는 stage 루트에 과목의 상대 경로 구조와 기존 노트/강의자료 읽기 연결을 준비한다. 현재 날짜 폴더는 일반 디렉터리이므로 공개 폴더에 초안이 쓰이지 않는다.
- 모든 초안과 수정은 `RUN/work/stage/복습노트/<range>/`에서 만든다. 8단계에서 HTML/MD/PDF 쌍과 그림을 모두 검증한 후에만 공개 폴더에 반영한다. 실패한 초안으로 기존 산출물을 덮어쓰지 않는다.
- **처음 조립할 때만**: `복습노트/<range>/`(그 아래 `.pack/` 포함, 또는 예전 형식인 `복습노트/` 바로 아래)에 이번 `range`의 산출물(`정리노트_<range>_*`, `복습문제_<range>_*`의 `.html`·`.md`·`.cards.json`·PDF, `figures_<range>/`)이 하나라도 있으면 먼저 백업한다. 다시 조립할 때(5~8단계에서 돌아온 경우)는 백업하지 않는다. 이미 스킬이 만든 초안이 백업에 섞이기 때문이다.
  - `RANGE`, `REPO`, `RUN`을 모두 실제 값으로 바꿔 한 명령으로 실행한다. 파일명은 NFC로 비교하므로 NFD 파일명도 잡힌다.
  - 백업은 매번 새 폴더 `RUN/previous-<시각>-<임의>/`에 만든다(이전 백업을 덮어쓰지 않음). `RANGE`가 형식에 안 맞거나, 대상이 있는데 복사된 파일 수가 다르면 종료 코드 1로 멈춘다. 이때는 조립하지 말고 원인을 고친다.
```bash
RANGE=<range> REPO=… RUN=… python3 - <<'EOF'
import os, re, shutil, sys, tempfile, time, unicodedata as u
r, run = os.environ["RANGE"], os.environ["RUN"]
notes = os.path.join(os.environ["REPO"], "복습노트")
if not re.fullmatch(r"\d{4}(-\d{4})?", r) or not os.path.isdir(run):
    sys.exit(f"백업 중단: RANGE={r!r} 또는 RUN={run!r} 잘못됨")
def want(n):
    n = u.normalize("NFC", n)
    return n.startswith((f"정리노트_{r}_", f"복습문제_{r}_")) or n == f"figures_{r}"
def listdir_nfc(d):  # NFD 폴더명도 찾는다
    return {u.normalize("NFC", n): os.path.join(d, n) for n in os.listdir(d)} if os.path.isdir(d) else {}
day = listdir_nfc(notes).get(r)
srcs = [day, day and listdir_nfc(day).get(".pack"), notes]  # 날짜 폴더, 그 아래 .pack/, 예전 형식(바로 아래)
hits = sorted({n: p for d in srcs if d and os.path.isdir(d) for n, p in listdir_nfc(d).items() if want(n)}.items())
if not hits:
    print("백업할 기존 팩 없음"); sys.exit(0)
def count(p):
    return sum(len(f) for _, _, f in os.walk(p)) if os.path.isdir(p) else 1
dst = tempfile.mkdtemp(prefix=time.strftime("previous-%Y%m%d-%H%M%S-"), dir=run)  # 항상 새 폴더
for n, a in hits:
    b = os.path.join(dst, n)
    shutil.copytree(a, b) if os.path.isdir(a) else shutil.copy2(a, b)
want_n, got_n = sum(count(a) for _, a in hits), count(dst)
if got_n != want_n:
    sys.exit(f"백업 실패: 파일 {want_n}개 중 {got_n}개만 복사됨 → {dst}")
print(f"백업 {len(hits)}항목(파일 {got_n}개): {dst}", *(a for _, a in hits), sep="\n")
EOF
```
```bash
python3 "$SKILL/scripts/review_pdf_stage.py" --run "$RUN" --repo "$REPO" --range "<range>"
python3 "$SKILL/scripts/assemble.py" --run "$RUN" --out "$RUN/work/stage/복습노트/<range>"
```

### 5. 기계 검사

- 미분 문항의 조건·본문·summary/sum·terms·힌트·카드/JSON·생성기 소개·MD가 같은 관례인지 확인한다. 검토에는 변수/미분 차원, 전치 단계, 원문 보존/수정 권한을 기록한다.
- 리뷰어에게 `RUN/learning-map.json`과 `references/big-picture-first.md`를 전달해, 도입만으로 학습 목표·비교 축·결과를 설명할 수 있는지 검토하게 한다. 본문에서 기존 결과 재사용·일반 공식의 대입·복원 요약이 이어지는지, 미분 관례·임시 기호 스케일·출처 경계가 일관되는지도 확인한다.
- 리뷰어에게 `references/narrative-flow.md`의 자기 검사 항목과 주 예시·관찰 비교 브리프를 전달한다. 주 예시가 섹션 끝까지 이어지는지, 계산 상자를 건너뛰어도 흐름이 이어지는지, 본문에 위치 표시가 남지 않았는지 확인한다. 적용 토픽에서는 관찰값이 첫 식의 어느 자리에 들어가는지 `연결 검토 근거`에 기록한다.
- 리뷰어 1명을 띄운다. 브리프는 `references/review-prompt.md`에 있다.
- 리뷰어 브리프의 `<학습 레퍼런스>`에는 3단계에서 전달한 적용 토픽 id와 필수 읽기 경로를 넣는다. 적용 대상이 없으면 `적용 없음`, 읽지 못했으면 `참고 누락: <원인>`으로 채운다.
- Critical과 Important는 모두, Minor는 쉬운 것만 고친다.
- 담당 작성자별로 **한 번에 모아서** 수정을 요청한다. 수정은 한 번만 한다.
- 수정 후 4~5단계를 다시 한다. 반영하지 않은 항목은 보고서에 적는다.

### 6b. 설명 감사
- 감사자에게 `references/learner-reasoning-patterns.md`, `references/narrative-flow.md`와 적용 토픽의 학습자 연결·관찰 비교 브리프를 전달한다. 같은 연결의 반복, 목적·대상 설명이 빠진 조건, 관찰에서 수식으로 넘어갈 때 빠진 연결을 본문으로 확인한다.

### 8. PDF 쌍·링크·MD 검증과 배포
- 미분 수식 변경은 원천 카드·JSON·해설 조각에서 시작해 다시 조립한다. 기존 HTML의 본문만 고쳐 완료하지 않는다. 문제 PDF와 답안 PDF의 조건·힌트·풀이까지 행 관례가 유지되는지 실제 페이지에서 대조한다. 예전 승인·해시를 새 검토로 재사용하지 않는다.
- `references/pdf-workflow.md`의 명령을 그대로 따른다. HTML은 stage에서 검사하고, 저장된 원시 카드로 PDF 쌍을 만든다. 미래 카드에는 `.problem` 직계 `.conditions`와 `.ask`가 필수다.
- 기본은 1920×1080 CSS px(1440×810pt)의 `video-16x9`이며 하단 180px은 흰 자막 여백이다. A4 문항별 본문·풀이·수식 배율을 먼저 측정해 화면 글자 크기를 보존한다. 인쇄용 A4가 명시적으로 필요하면 `--layout a4`를 사용한다.
- `build_review_pdf.py --stage-only`가 성공한 PDF 둘만 stage의 날짜 폴더 바로 아래에 복사한다. `add_pdf_links`로 노트에 문제지/해설지 링크를 넣고 실제 카드 수를 안내한다. manifest의 links 토픽에 두 PDF 링크를 추가한 후 다시 HTML 검사한다.
- PDF 링크 적용 후 `html2md.py --check`를 출력 경로 지정 없이 실행해 발행용 MD 두 개와 그림을 stage의 `.pack/`에 만든다. MD의 `../` PDF 링크가 HTML과 같은 파일을 가리키는지 확인한다. 관찰 비교가 있는 정리노트는 변환된 MD에서도 같은 대표 값이 첫 식으로 이어지는지 확인한다. PDF 전체 페이지를 PNG로 렌더링하여 표·화살표·수식·필기 공간·Hint·계속 페이지를 모두 눈으로 확인한다.
- PDF skill을 사용할 때 첫 PDF 작성 직전 authoring marker를 한 번 수행한다. 실행 중 두 템플릿과 video CSS는 변경하지 않는다. EC2 `757fa081521008d46542e23d5a1a53112391aed2`에서 고정 복사한 세 파일의 `pdf-template-provenance.json` 해시를 확인한다.
- 두 PDF, 정리노트 HTML, MD 두 개, 모든 참조 그림이 준비된 후 `publish_pack`으로 문항 원고까지 함께 배포한다. 백업은 `RUN/work/backups/`다. 교체 실패 시 기존 파일을 복구한다.
- KaTeX·폰트·이미지 로드 실패, 넘침, 정답 검증 실패 또는 PDF 둘 중 하나의 실패는 해당 팩 배포 실패다. 이미 있는 파일을 보존하고 원인/문제 id를 보고한다. HTML/MD만으로 완료라고 보고하지 않는다.

- 기본 팩 배포 성공 직후 [문제설명 공통 절차](references/problem-explain.md)를 발행된 `.pack/복습문제_<range>_<slug>.cards.json`의 정확한 절대 경로로 실행한다. 신규·기존 팩 갱신 모두 전체 문항·소문항을 처리한다. 설명 실패는 기본 팩을 보존하고 별도로 보고한다.

- 기본 팩 배포와 문제설명 처리 뒤 [기존 인터랙티브 연결 복원](references/interactive-links.md)을 적용한다. 기존 자료가 있을 때만 재연결하며 새 자료는 자동 생성하지 않는다. 연결 오류는 기본 팩·문제설명 결과와 분리해 보고한다.

### 확인문제 자동 생성

- 8단계에서 **신규** 기본 팩 발행이 성공하면 이어서 [ml-concept-check/SKILL.md](../ml-concept-check/SKILL.md)의 절차를 같은 `range`로 실행한다. 문제설명 시도와 기존 인터랙티브 연결 복원을 마친 뒤 시작한다. 두 후속 작업의 성공 여부와 관계없이 실행한다. 실행 종류는 0단계에서 판단한다. 기존 팩의 재조립·설명 갱신에는 자동 생성 절차를 호출하지 않는다.
- 확인문제에 별도 RUN을 만들고 `quiz.py prepare <range> --run <확인문제 RUN> --manifest <복습팩 RUN>/manifest.json`을 실행한다. 최종 경로의 노트와 STT를 사용한다. 현재 복습팩 RUN의 요약을 작성 근거로 함께 사용할 수 있다. 확인 목표를 고르고 문항을 작성한 다음 블라인드 풀이와 네 가지 오프라인 브라우저 검증을 거쳐 발행까지 마친다.
- 스킬·근거 파일 누락, 검사 실패, 발행 실패는 “복습팩 생성됨 / 확인문제 보류”로 보고한다. 기본 팩, 이전 확인문제와 설명은 보존하고 실패 원인과 확인문제 RUN을 적는다.

## 본문과 우측 패널 표시 계약

중앙 주제·문항 제목과 패널의 고정 제목은 유지한다. 우측에는 중앙 제목을 복사하지 않는다. `sum-for`는 제목이 아닌 유일한 `.sums` 컨테이너 ID로 보존한다. `.sum` 전환, 문제·원문 탭, 힌트·풀이, 앵커, read/solved 저장 키와 payload를 유지한다. 예습·과제·시험도 같은 표시 계약을 따른다.

요약은 같은 토픽 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축한다. 식·용어·항목 수에 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않으며 보충의 범위·출처·불확실성을 보존한다. 문제설명은 풀이의 판단 조건·결론·단서를 압축하고 문제 데이터와 풀이 본문을 바꾸지 않는다.

검토 시 자료·토픽별로 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 기록하고 본문 주장, 대응 요약 문장, pass/unresolved와 생략 이유를 대조한다. 보완 후 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고도 동기화하되 원래 없는 MD 형식은 만들지 않는다. 요약·예고·링크 화면의 기존 구조를 유지한다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. 실제 검사 뒤에만 status를 바꾸며 HTML·감사표 해시 변경 후에는 기록을 갱신해야 한다.
