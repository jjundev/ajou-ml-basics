# 긴 유도·계산의 단계형 본문

긴 계산을 중앙 화면에서 연속으로 읽되, 현재 구하는 대상과 다음에 쓸 결과를 찾을 수 있게 한다. 서로 다른 계산 목적이 이어질 때 적용한다. 짧은 정의·큰 그림·요약·예고·자료 링크에는 단계를 강제하지 않는다. 단계 수는 내용에 맞추고 다섯 개로 고정하지 않는다.

## 보존 범위

- **레이아웃만 수정할 때**는 `쉽게 말하면`을 포함한 기존 문장·그림·캡션·수식을 그대로 둔다. 원문을 생략하거나 선택적 펼치기로 숨기지 않는다.
- **설명 축약·개선 요청일 때**는 `problem-solving-depth.md`에 따라 필요한 연결을 보존하면서 중복·주변 설명과 수식을 선별 편집한다. 독립적 가치가 있는 별도 증명은 선택 보충으로 둘 수 있다. 필요한 결론·조건·대표 유도는 보이는 본문에 남기고, 링크 도착점·단계 번호를 실제 읽기 경로에 맞춘다.
- 좌우 패널의 마크업·스타일·너비 조절·모바일 드로어, 페이지 이동·테마·읽음 저장 키와 payload를 유지한다. 내용 편집 시 요약도 본문과 동기화한다. 단계형은 중앙 본문의 하위 구조다. 비교용 HTML의 전체 화면 틀을 가져오지 않는다.
- `.sum`은 기존대로 토픽의 직계 자식이며 맨 끝에 둔다. 본문의 단계 결과로 우측 요약을 대체하거나 중복 패널을 만들지 않는다.
- 기존 토픽 ID, 인용·보충 구분과 인터랙티브·PDF 링크를 보존한다. HTML과 기존 대응 MD를 함께 갱신한다.

## 읽는 순서

1. 기존 도입 뒤 `정확히 말하면` 안에 계산 단계 이동 링크를 둔다. 계산이 별도 `보충` 레이어에만 있으면 링크와 단계도 그 안에 두어 수업 본문·교수님 말씀·위젯의 기존 위치와 경계를 보존한다. 제목은 고윳값·고유공간처럼 계산 대상을 짧게 표시한다. 실제 앵커 링크라서 키보드 이동과 직접 URL도 작동해야 한다.
2. 각 단계는 **번호와 제목 → 앞 단계가 남긴 질문과 이 단계의 목표 한 문장 → 계산 소제목·설명·수식 → 결과와 다음 단계가 이어받을 질문** 순서로 쓴다. 질문은 문장 안에 녹이고 라벨로 붙이지 않는다(`big-picture-first.md`의 ‘질문 순서로 본문 잇기’). 단계와 소제목은 숨김 없이 이어서 읽힌다.
3. 번호는 단계 제목과 이동 링크에만 둔다. 본문 소제목의 `1단계`, `2단계`와 옛 번호를 가리키는 문장은 제거하거나 의미로 연결한다. 내부 알고리즘의 실제 연산 순서가 필요한 `ol.steps`는 유지한다.
4. 설명·목표·결과는 원본과 같은 해요체로 쓴다. 제목은 짧은 명사구도 허용한다. 수식 표기를 본문·요약에서 일관되게 유지한다.
5. 단계 결과는 `<p class="note-stage-result"><b>여기서 얻은 결과.</b> …</p>`처럼 기존 본문과 같은 일반 문단으로 쓴다. 문장으로 된 결과에는 배경색·테두리·별도 배지를 붙인 결과 카드를 만들지 않는다. 예외는 아래 식 줄 서식의 마지막 식(`li.deriv-gen`) 하나뿐이다. 이미 결과가 명확하면 반복하지 않는다. 마지막에 기존 `복원 순서`·`복원 요령` 문단이 있으면 이를 유지하고 별도 결과 요약을 덧붙이지 않는다.

## 식 줄 + 주석

유도 본문은 문단과 식을 번갈아 쓰지 않고, **식을 한 줄씩 세우고 그 줄의 연산·이유를 옆에 한 줄로 단다**. 독자는 식만 따라 내려가며 흐름을 보고, 막힌 줄에서만 주석과 펼친 설명을 읽는다.

**쓸 때**: 식 3개 이상이 앞 식에서 이어지는 유도, 같은 모양으로 늘어놓는 정의·조건 목록(주어진 것·고정·구할 것), 각 줄이 식인 절차(전처리 → 사영 → 복원). **쓰지 않을 때**: 개념·동기·비교를 말로 설명하는 문단, 식 1~2개짜리 짧은 단계, 표가 더 맞는 내용. 이런 부분은 일반 문단으로 쓰고, 식 줄 앞뒤에 둔다.

```html
<div class="note-stage">
  <h4 class="note-stage-title" id="…">…</h4>
  <p class="note-stage-goal">이 단계의 목표 한 문장.</p>
  <div class="deriv-body">
    <p class="deriv-legend">파란색은 바로 윗줄에서 바뀐 부분이에요.</p>
    <p class="deriv-lead">필요할 때만: 출발 조건이나 왜 이렇게 하는지 한두 문장.</p>
    <ol class="deriv">
      <li><div class="deriv-eq">$$V(\mathbf b)=\mathbf b^\top\mathbf S\,\mathbf b$$</div>
          <div class="deriv-why"><p>1단계에서 만든 식</p></div></li>
      <li><div class="deriv-eq">$$\hphantom{V(\mathbf b)}=\textcolor{#3182f6}{(c_1\mathbf p_1^\top+c_2\mathbf p_2^\top)}\,\mathbf S\,(\ldots)$$</div>
          <div class="deriv-why"><p>$\mathbf b=c_1\mathbf p_1+c_2\mathbf p_2$ 대입</p>
            <details><summary>자세히</summary><p>왜 이 대입이 필요한지, 한두 문장.</p></details></div></li>
      <li class="deriv-gen"><div class="deriv-eq">$$V(\mathbf b)=\sum_i\lambda_ic_i^2$$</div>
          <div class="deriv-why"><p>축이 $D$개일 때</p></div></li>
    </ol>
    <p class="note-stage-result"><b>결론 한 문장.</b> 필요하면 한 문장 더.</p>
    <p class="deriv-check">예: 숫자 대입·주의 사항을 짧게.</p>
  </div>
</div>
```

- **줄 하나 = 연산 하나**: `.deriv-eq`에는 `$$…$$`가 정확히 1개다. 같은 연산의 두 식(예: $\mathbf p_i^\top\mathbf p_i=1$, $\mathbf p_i^\top\mathbf p_j=0$)은 `\qquad`로 한 줄에 둘 수 있다.
- **앞 유도의 재사용**: 다른 곳에서 얻은 **결과 식 하나**를 대입하는 것은 한 줄이다. 앞 유도의 **절차**(연산 둘 이상)를 다른 변수로 다시 밟을 때는 줄을 생략하지 않고 앞과 같은 줄 수로 쓰며, 각 줄 주석 끝에 `(앞에서: <a href="#단계id">단계 이름</a>)`처럼 대응 단계를 링크한다. "~와 같은 세 연산"처럼 참조 하나가 여러 줄을 대신하는 주석이나, 중간식을 `자세히` 안에만 두는 줄은 쓰지 않는다. `check_html.py`의 `deriv-bundled` 검사가 이 두 모양을 막는다.
- **주석은 늘 보인다**: `.deriv-why`의 첫 `<p>`는 비울 수 없고, 그 줄에서 한 연산이나 쓴 사실을 한 줄(약 25자)로 말한다. 예: "곱의 전치는 순서가 뒤집혀요", "다른 축끼리 내적 0, 같은 축 1". 핵심 연결(어떤 성질·식을 썼는지)은 이 줄에 둔다.
- **펼치기에는 보충만**: `자세히`에는 그 연산이 왜 성립하는지에 대한 부연, 용어 이름, 같은 내용의 다른 표현을 둔다. 조건·결론·다음 단계가 쓰는 결과는 펼치기 안에만 두지 않는다. 펼칠 내용이 없으면 `details`를 쓰지 않는다.
- **정렬**: 같은 좌변을 잇는 줄은 `\hphantom{좌변}=`으로 시작해 `=` 위치를 맞춘다.
- **강조**: `\textcolor{#3182f6}{…}`는 `.deriv` 안에서만, 바로 윗줄과 달라진 부분(대입한 항, 바뀐 인자)에만 쓴다. 한 줄에 1~2곳. 토픽에서 처음 강조를 쓰는 단계에 `deriv-legend`를 한 번 둔다. 색은 CSS가 테마별로 바꾸므로 다른 색 값을 쓰지 않는다.
- **마지막 식**: 그 단계가 다음 단계·토픽에 넘기는 식은 `li.deriv-gen`(회색 상자)으로 한 번만 둔다. 문장 결과는 `note-stage-result` 일반 문단이다.
- **숫자 예와 주의**: 유도 줄 사이에 끼우지 않고 `deriv-check` 문단으로 아래에 둔다. 예 자체가 식 연쇄이면 `note-subheading` 아래에 별도 `ol.deriv`로 쓴다.
- **소제목**: 한 단계 안에서 주제가 바뀌면 `deriv-body` 안에 `h5.note-subheading`을 두고 새 `ol.deriv`를 시작한다.
- **간격**: CSS가 정한다(덩어리 사이 24px, 짝을 이루는 줄 8px, 식 줄 안쪽 12px). 인라인 `style`이나 빈 문단으로 간격을 조절하지 않는다.
- **긴 식**: 주석 칸 옆에 다 들어가지 않는 줄은 템플릿의 `deriv-fit` 스크립트가 주석을 식 아래로 내린다. 375px에서도 한 줄로 길면 식을 둘로 나누거나 정의 부분을 주석으로 옮긴다.
- **MD**: `html2md.py`가 줄마다 `$$식$$`과 `↳ 주석`, `<details>`로 옮긴다. 번호 목록으로 바꾸지 않는다.

## 마크업과 템플릿

`assets/note-template.html`에 단계형 스타일과 이동 링크의 현재 단계 표시, 식 줄 서식(`/* 식 줄 + 주석 */` CSS 블록과 `deriv-fit` 스크립트)이 포함돼 있다. 새 노트는 조립기로 이 템플릿을 사용한다. 기존 노트에 적용할 때는 이 전용 CSS와 `note-stage-navigation`·`deriv-fit` 스크립트만 추가한다. 전체 템플릿 교체로 기존 위젯·패널 코드를 덮어쓰지 않는다.

```html
<div class="layer formal"><span class="layer-title">정확히 말하면</span>
  <nav class="note-stage-nav" aria-label="계산 단계">
    <a href="#example-values" aria-current="step">1. 고윳값</a>
    <a href="#example-vectors">2. 고유공간</a>
  </nav>
  <p>예제의 목적과 출발 조건이에요.</p>
  <div class="note-stage">
    <h4 class="note-stage-title" id="example-values"><span class="note-stage-number">1 / 2</span><span>가능한 배율 찾기</span></h4>
    <p class="note-stage-goal">영벡터가 아닌 해가 존재할 조건으로 고윳값을 구해요.</p>
    <h5 class="note-subheading">특성방정식을 풀어요</h5>
    <p>기존 설명과 수식이 이어져요.</p>
    <p class="note-stage-result"><b>여기서 얻은 결과.</b> 구한 값을 다음 계산에 대입해요.</p>
  </div>
  <!-- 다음 단계도 같은 구조. ID는 문서 전체에서 유일하게 쓴다. -->
</div>
```

단계 제목은 `h4`, 계산 소제목은 `h5`다. 토픽 제목을 찾는 기존 `h3` 선택자와 충돌하지 않게 한다. 단계 컨테이너는 `div`로 만들며, 기존 페이지 단위인 `main > section`을 추가하지 않는다. 수식은 텍스트만 옮겨 원래 순서를 유지한다.

## 글자 위계

크기를 중요도와 역할에 따라 정하고, 본문이 길다는 이유로 작게 줄이지 않는다. 기존 패널에는 이 표를 새로 적용하지 않는다.

| 역할 | 데스크톱 / 375px | 굵기 | 줄높이 |
|---|---|---|---|
| 토픽 제목 `h3` | 32 / 26px | 800 | 1.3 |
| 단계 제목 `.note-stage-title` | 24 / 22px | 700 | 1.4 |
| 쉽게 말하면 핵심 문장 `.lead` | 22px | 700 | 1.5 |
| 레이어 제목·계산 소제목 | 19px | 700 | 1.4 |
| 본문·목표·결과 | 17px | 400 | 1.7 |
| 본문 안 짧은 강조 | 17px | 700 | 본문과 같음 |
| 인용·보조 설명 | 15px | 400 | 1.7 |
| 그림 설명 | 14px | 400 | 본문과 같음 |
| 단계 번호·메타 정보 | 13px | 600 | 역할에 맞춤 |

모바일에도 본문 17px를 유지한다. 새 강조를 문단 전체에 적용하지 않는다. 수식은 기존 KaTeX 크기와 가로 스크롤을 유지한다. 단계 사이에는 큰 여백과 얇은 구분선, 소제목 위에는 아래보다 넓은 여백을 둔다. 이동 링크는 좁은 화면에서 가로로 스크롤하고 본문 전체를 옆으로 밀지 않는다.

## 검증

기존 노트 갱신 시 직계 `.sum`·좌우 패널·수정 범위 밖 토픽의 보존을 대조한다. 레이아웃 전용 변경은 TeX 목록과 순서의 동일성을 확인한다. 내용 편집은 승인 범위의 삭제·축약·보충과 남길 최소 연결을 대조하고 HTML·MD·요약을 함께 확인한다. 단계 번호 중복, 문장 결과 카드, 접혀 숨은 핵심 설명이 없는지 읽는다. 식 줄에서는 펼치지 않고 식과 주석만 읽어도 각 줄의 연산과 단계 결론이 이어지는지 확인한다. `check_html.py`의 `deriv-row` 검사(줄마다 수식 1개, 보이는 주석)를 통과해야 한다.

375px와 데스크톱, 라이트·다크에서 글자 위계·수식·가로 넘침·이동 링크·현재 단계 표시를 확인한다. 깊은 단계로 이동한 뒤 이전/다음과 목차로 다른 토픽을 방문하고 돌아와도 제목·우측 요약·읽음 상태가 정확해야 한다. 기존 HTML·learning-map 검사와 HTML/MD의 수식·앵커·링크 대조를 수행한다.
