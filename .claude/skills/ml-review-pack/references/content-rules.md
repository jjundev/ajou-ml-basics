- 자기 검사(끝내기 전): 토픽별로 `required_terms`가 모두 문자 그대로 들어갔는지, `$` 짝, `links` 항목이 해당 토픽 안에 있는지, 금지어 `<forbidden 목록>`이 없는지. 금지어는 예고 토픽 `<preview_topic>` 안에서만 허용된다 — 이 토픽에는 예고 제목을 빠뜨리지 말고 쓴다. eli5 레이어마다 문장 수(figcaption 포함)가 3 이하이고 전문용어·기호(θ, σ, 식, 영어 용어)가 없는지 — 있으면 formal 레이어로 옮긴다. 조각 어디에도 이모지를 쓰지 않았는지. `layers`가 빈 목록이 아닌 토픽마다 마지막에 `<div class="sum" hidden>`이 있고, 그 식·용어가 본문과 같은 표기인지. 그림 설명(글, `aria-label`)이 SVG 클래스의 실제 모양(채움/윤곽)과 맞는지.
- 보고: 파일 경로, 토픽별 한 줄, 요약에 있었지만 넣지 않은 것과 이유.
- 공분산 레퍼런스를 적용한 토픽의 자기 검사(`lite` 포함): 가중합과 스칼라 지식의 연결이 있는지, 일반 규칙의 계수 위치·전치·차원이 정확한지, 교차/자기 공분산을 구별했는지 확인한다. 설명됨과 숙달·미확인을 혼동하지 않았는지, 원자료 없이 수업 범위를 넓히거나 교수님 발언을 만들지 않았는지도 확인한다. 확인 예제는 관련 설명에 필요할 때만 쓰며 문제 카드로 자동 추가하지 않는다. 보고에 적용 토픽 id와 사용한 설명 연결을 적는다.

## 큰 그림과 수식의 연결
- `big-picture-first.md`를 전체 읽고 메인의 `RUN/learning-map.json` 브리프를 따른다. 첫 학습 토픽은 오늘의 질문·관계·결과·유도 목적·혼동을 수식 전개보다 먼저 설명한다.
- 큰 그림 토픽은 formal 레이어 하나로 작성할 수 있고 기호를 쓸 수 있다. 다른 토픽도 `manifest-guide.md`에 따라 설명 기능이 필요한 레이어만 선택한다.
- 각 유도는 구하려는 대상과 계산 목적을 먼저 한 문장으로 연결한다. 기호의 첫 등장에는 뜻·차원·역할을 설명한다. 임시 묶음은 임시 이름임을 밝힌다.
- 섹션 하나가 독립적으로 읽혀도 목표가 보이도록 하되, 큰 그림 표 전체를 모든 섹션에 반복하지 않는다.
- 연결 중심 작성: 필요한 출발식 상기, 변경점 비교, 한 연산씩 유도, 다음 결과의 대입 위치, 복원용 요약을 관련 개념 묶음에 적용한다. 표·비유·기호 정의를 각 토픽에 일괄 반복하지 않는다.
- 핵심 전환은 `big-picture-first.md`의 ‘핵심 전환을 작성하고 검토하는 방법’에 따라 기존 저작 브리프에 출발식·도착식, 예상 질문과 필요한 연결을 적고 본문에 반영한다. 새로 묶은 표기의 뜻과 실제 대입·전개를 구별해 연결한다. 자기 검토에서도 본문의 근거와 자신이 보충한 연결을 대조하며 신규·기존 수정·lite에 적용한다.
- 일반 공식은 이름만 언급하지 않고 이번 문제의 변수·계수 대응을 보인다. 알고 있던 공식을 짧게 상기한 뒤 적용하며, 필요한 때만 정의·성분 계산으로 확장한다. 공분산 관련 설명은 기존 레퍼런스와 중복시키지 않는다.
- 수업 공식·동치인 재표현·추가 직관을 등장 지점에서 구분한다. 짧은 동치 연결은 재표현이라고 밝히고 원래 공식도 남긴다. 수업 미유도 상세 증명은 기존 범위·supp 계약을 따른다. 필수 연결을 선택적 펼치기에만 넣지 않는다.
- 자기 검사(lite 포함): 핵심 결과가 다음 유도의 입력으로 이어지는가, 대입·전치·역행렬을 생략하지 않았는가, 행벡터 미분과 기호 스케일이 일관되는가, 출처와 가정이 분명한가, 반복 문단을 줄일 수 있는가. 체크 단어의 존재만으로 이해 가능성을 승인하지 않는다.
- 수식의 의미 연결(신규·기존 수정·lite): 압축된 식이 성질을 나타내는 토픽에서는 필요한 성분·내적 등 익숙한 연산으로 펼치고, 각 값의 의미를 연결한 뒤 전체 조건·역할로 다시 묶는다. 조건을 선언한 문장만으로 설명이 충분하다고 판단하지 않는다. 성립 조건과 동치·단방향을 구별하며 핵심 연결은 펼치기 안에 숨기지 않는다. 이미 충분한 연결이나 모든 산술에 일률적으로 긴 전개를 요구하지 않는다.
- 변형 전후 성질 보존: 대상이 바뀌어도 성질이 유지된다고 할 때 허용되는 변화의 범위와 유지되는 이유를 설명한다. 이전 개념을 재사용하면 기호 대응과 결과의 쓰임을 연결한다. 자유롭게 바꿔도 유지되는 성질과 특정 계수로 추가 달성하는 조건을 구별한다. 공간적 설명이 유효하면 익숙한 축·평면으로 먼저 연결하고 짧은 식으로 확인하되 모든 주제에 공간 비유를 강제하지 않는다. 결과 검산만으로 보존 이유까지 설명됐다고 판단하지 않는다. 신규·기존 수정·lite에 동일하게 적용한다.
- 학습자 연결 자기 검사(lite 포함): 각 기호가 무엇을 모았고 어떤 역할인지, 자연스러운 대안을 왜 이번 목적에 쓸 수 있거나 없는지 본문으로 설명할 수 있는가. 정의·추가 조건·보장·선택을 구별하는가. 적용한 연결과 미해결을 보고하며, 무관한 주제에 고유벡터 예제를 반복하지 않는다.

## 계산을 시작하고 전환할 때
- `big-picture-first.md`의 ‘연산을 시작하는 이유와 계산 대상의 연결’을 적용한다. 핵심 연산 앞에서 구할 대상·출발 조건·연산 선택 목적을 연결하고, 그 변형의 허용 근거를 설명한다.
- 행렬식에서 고유벡터 방정식처럼 계산 대상이 바뀌면 앞에서 구한 값의 대입 위치와 새 미지수를 밝힌다. 행렬·벡터 표기에서 성분식으로 처음 전환할 때는 실제 한 성분의 곱셈·합산을 보여 준다.
- 구조를 이용한 계산 단축은 적용 조건을 밝히고, 기본 절차를 익히는 예제에서는 일반 계산을 먼저 제시한다. 작성 후 본문만 읽고 연산 선택 이유와 첫 성분 계산을 재현할 수 있는지 점검한다.

## 범위
- 요약의 슬라이드 대조표에서 "다룸/일부"인 내용만 쓴다. "예고만/안 다룸"은 `s<N>-next`에 제목만.
- 강의의 핵심 개념·결과·조건과 풀이에 필요한 칠판 유도를 싣는다. 비유·일화·강조 발언은 실제 판단을 돕는 것을 선별한다. 같은 의미의 비유나 대화 복기로 분량을 채우지 않는다. 제외한 핵심 후보와 이유는 RUN에 기록한다.
- STT 오인식·말실수·슬라이드 오타는 올바른 개념·식·조건으로 설명한다. 정리노트 HTML과 대응 MD에 전사·발언·오타를 바로잡은 편집 경위는 쓰지 않는다. "수업 중 X로 말했다가 정정", "구두로 여러 수치가 언급돼 여기서는 Y를 사용", "STT의 X는 Y" 같은 문장과 영문 철자 오타 지적은 제거한다. 필요한 수학적 구분은 정확한 내용만 직접 설명하고, 보충 여부·가정·불확실성은 유지한다.

## 긴 계산의 본문 서식

긴 유도·계산은 [단계형 본문](staged-body.md)을 따른다. 목적·풀이·결과를 묶되 짧은 토픽에는 단계를 강제하지 않는다. 기존 노트의 도입·좌우 패널을 유지하고 결과는 일반 문단으로 쓴다. 단계 안의 유도는 같은 파일의 **식 줄 + 주석** 서식(`ol.deriv`)으로 쓴다. 식을 한 줄씩 세우고 연산·이유는 옆 한 줄 주석에 두며, 문단과 식을 번갈아 쓰지 않는다.

## 토픽 마크업 (이 순서)
```html
<article class="topic" id="…"><h3>…</h3><div class="tags"><span class="tag date">MMDD 수업</span><span class="tag slide">L0X sN</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">한 문장 비유</p> …그림… </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span> …정의·수식·단계별 유도(식 줄 ol.deriv, 알고리즘 순서는 ol.steps)… </div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span> …비유·일화, 원문은 blockquote… </div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span> …강조 발언 원문 인용… </div>   ← 강조 발언이 있을 때만
  <div class="layer supp"><span class="badge supp">보충 · 수업에서 유도하진 않았어요</span> … </div>             ← manifest supp=true만
  <div class="sum" hidden>…페이지 요약(아래)…</div>                                                    ← layers가 빈 목록이 아닌 토픽만, 맨 끝
</article>
```
- 레이어 제목과 배지 글자는 위와 글자 그대로 쓴다. 이모지, 장식 기호(★, ↗, → 같은 화살표 아이콘), "아래를 보세요" 같은 안내 문장은 쓰지 않는다.
- 템플릿이 토픽 하나를 한 화면에 보여 준다. 토픽은 그것만 읽어도 이해되게 쓰고, "위에서 본 것처럼"처럼 앞 토픽의 위치에 기대는 말 대신 `<a href="#토픽id">토픽 제목</a>`으로 잇는다.
- 요약·예고 섹션: 치트시트는 표(`<div class="table-wrap"><table>`), 예고는 `<ul>`, 링크는 `<ul><li><a>`.
- 복습문제 링크는 `href="{{REVIEW_HREF}}"`로 쓴다(조립기가 실제 파일명으로 바꾼다. manifest의 파일명을 그대로 써도 된다). 다른 링크는 manifest `href`를 글자 그대로.

## 페이지 요약 (`.sum`)
화면 오른쪽 "페이지 요약" 패널에 그 토픽의 핵심만 보여 준다. 템플릿이 토픽의 **직계 자식** `.sum`을 패널로 옮기므로 토픽 안 맨 끝에, 레이어 밖에 둔다. `hidden`은 꼭 붙인다(본문에 두 번 보이지 않게).
```html
<div class="sum" hidden>
  <p class="sum-lead">토픽 핵심 한 문장("~해요" 체)</p>
  <p class="panel-label">핵심 식</p>
  <ul class="eq-list"><li><span class="eq-name">식 이름</span>$$…$$</li></ul>
  <p class="panel-label">용어</p>
  <dl class="terms"><dt>용어(영어)</dt><dd>한 줄 뜻</dd></dl>
</div>
```
- 새 내용을 쓰지 않는다. 본문에 이미 나온 핵심 개념·식·용어를 **같은 TeX 표기로** 필요한 만큼 고르며 작동 원리·성립 조건·혼동 구분을 보존한다. 개수에 고정 상한을 두지 않는다. 요약에만 있는 식이나 설명은 두지 않는다.
- 식이 없는 토픽은 "핵심 식" 줄과 `eq-list`를 빼고, 용어가 없으면 "용어" 줄과 `dl`을 뺀다. `sum-lead`는 항상 쓴다.
- 요약·예고 섹션처럼 `layers`가 `[]`인 토픽에는 두지 않는다.

## 문체
- 쉽게 말하면(eli5): 초등학생이 이해할 1~3문장(figcaption 포함) + 그림. 전문용어·기호 없이(필요하면 정확히 말하면에 쓴다). 토스처럼 짧고 다정한 "~해요" 체.
- 정확히 말하면(formal): 필요한 판단·조건·연결을 정확하게. 대표 유도의 핵심 연산은 한 줄에 한 단계로 쓰고(식 줄 + 주석), 이미 설명한 원리는 식·기호 대응으로 짧게 상기한다. 문장은 "~해요" 체로 쓴다.
- 교수님 말씀(prof)/꼭 기억해요(warn): 원문 인용은 15단어 안팎으로 줄인다. 녹음 타임스탬프와 파트·시각 범위는 STT 요약에서 근거 확인에만 사용한다. 시각 없는 "(1104 Parts 06–07)", "1104 전사 Part 02", "Part 03에서는", "정확한 시각 없음"도 정리노트 HTML·대응 MD의 인용, 본문, 요약, 그림 설명, 각주, footer에 옮기지 않는다. 강의 제목의 "PCA Part1"과 일반적인 슬라이드·교과서·자료 출처는 유지한다.
- UI 글은 한국어, 전문용어는 영어 병기(예: 과적합(overfitting)). 한 문장에 한 가지만 말하고, 군더더기 수식어("아주", "정말", "한번")는 뺀다.

## 수식
- `$…$`(인라인), `$$…$$`(디스플레이)만. 본문에 리터럴 `$` 금지.
- TeX 안에 `<`, `>`, `&` 금지 → `\lt`, `\gt`. 정렬 환경 대신 `$$` 줄을 나눈다.
- PDF 템플릿은 40자가 넘고 중괄호·`\left…\right` 바깥에 관계 기호(`=`, `\le(q)`, `\ge(q)`, `\approx`, `\Rightarrow`)가 있는 `$…$`를 display로 바꾸고 관계 기호마다 줄을 나눈다. 문장 속에 한 줄로 두려는 긴 식(행렬 정의 `A=\begin{bmatrix}…\end{bmatrix}` 등)은 식 전체를 `${…}$`처럼 중괄호로 감싼다. 여러 식을 쉼표로 나란히 쓸 때도 식마다 감싼다(`${\mathbf{A}=…},\quad{\mathbf{B}=…}$`).
- 미분 관례: `vector-derivative-convention.md`를 따른다. 해당 수업의 스칼라 목적함수 미분은 행벡터로 쓰며, 열벡터 방정식으로 옮길 때 양변 전치를 명시한다. 파라미터 벡터 자체를 행벡터로 바꾸는 것은 아니다. 본문·summary/sum·terms·보충 패널에도 적용하고, 기존 원문의 명시적 다른 관례는 보존 분기를 따른다.
- 벡터는 `\mathbf{x}`, 파라미터 벡터는 `\boldsymbol{\theta}`, 행렬 `\mathbf{X}` — manifest `required_terms`와 같은 표기.

## SVG 그림
- eli5 레이어를 선택한 개념 토픽에는 실제 설명을 돕는 그림 1개 이상을 둔다(흐름도, 막대, 곡선 등). 그림·비유를 넣으려고 불필요한 eli5 레이어를 만들지 않는다.
- `<figure class="figure"><svg id="fig-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만: `fig-ink`, `fig-accent`, `fig-danger`, `fig-dot`, `fig-text`, `fig-muted`. 하드코딩 색 금지(다크모드).
- 채움과 윤곽: `fig-ink`, `fig-accent`, `fig-danger`는 선만 그린다(`fill:none`). 속이 칠해진 점·도형은 `fig-dot`(강조색 채움)뿐이다(`fig-text`, `fig-muted`는 글자용). 글·figcaption·`aria-label`에서 "색칠된", "채워진"은 `fig-dot` 도형에만 쓰고, 선만 있는 도형은 "테두리", "선"으로 부른다.
- 글자 12~14px, SVG `<text>`에 `$` 금지(θ, σ, ₁ 같은 유니코드).
- id는 페이지 전체에서 유일해야 한다(`fig-` + 토픽 고유 단어).

## PDF 연결
노트의 마지막 links 토픽에 PDF 문제지/해설지 링크를 메인 에이전트가 검증 후 삽입한다. 기존 review HTML link는 유지하고 문항 수는 실제 카드 수로 계산한다.

## 본문과 우측 패널 표시 계약

중앙 주제·문항 제목과 패널의 고정 제목은 유지한다. 우측에는 중앙 제목을 복사하지 않는다. `sum-for`는 제목이 아닌 유일한 `.sums` 컨테이너 ID로 보존한다. `.sum` 전환, 문제·원문 탭, 힌트·풀이, 앵커, read/solved 저장 키와 payload를 유지한다. 예습·과제·시험도 같은 표시 계약을 따른다.

요약은 같은 토픽 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축한다. 식·용어·항목 수에 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않으며 보충의 범위·출처·불확실성을 보존한다. 문제설명은 풀이의 판단 조건·결론·단서를 압축하고 문제 데이터와 풀이 본문을 바꾸지 않는다.

검토 시 자료·토픽별로 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 기록하고 본문 주장, 대응 요약 문장, pass/unresolved와 생략 이유를 대조한다. 보완 후 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고도 동기화하되 원래 없는 MD 형식은 만들지 않는다. 요약·예고·링크 화면의 기존 구조를 유지한다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. 실제 검사 뒤에만 status를 바꾸며 HTML·감사표 해시 변경 후에는 기록을 갱신해야 한다.
