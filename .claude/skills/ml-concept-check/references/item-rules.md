# 머신러닝기초 확인 목표와 문항

수업에서 이번에 배운 대상의 구성·역할, 공식의 적용 조건, 결과 해석을 확인한다. 근거는 STT와 대응 정리노트 토픽이다. 예고, 관련 링크, 수업에서 다루지 않은 교과서 심화, 기존 복습문제의 재출제는 제외한다. 이미 배운 개념은 새 개념을 판단하는 데 필요한 조건으로 사용할 수 있다.

## 목표

`objectives.json` 예시

```json
{
  "range": "1111",
  "slug": "Gaussian_Mixture_Models",
  "objectives": [
    {
      "id": "o1",
      "topic_id": "s2-responsibility",
      "concept": "관측한 점에서 성분별 기여를 사후확률로 정규화하기",
      "source": {"date": "1111", "locator": "Part 08, 베이즈 룰로 책임도 유도"}
    }
  ]
}
```

`topic_id`는 `scope.json` 목록에서 고른다. `locator`는 실제 STT 절과 짧은 찾기 단서다. 개념 이름과 근거 위치는 문항 화면에 공개하지 않는다. 보통 6~16문항을 쓰며 목표당 1~2문항이다.

## 문항

`items.json`은 `{"items":[...]}`다. 각 문항에 아래 필드를 넣는다.

- `id`는 `q1`부터 순서대로, `objective`는 목표 ID다.
- `title`은 판단할 주제만 알려 주고 정답을 밝히지 않는다.
- `stem_html`은 발문이다. 수식은 `$…$` 또는 `$$…$$`를 쓴다. HTML 요소는 `p`, `em`, `strong`, `b`, `i`, `br`, `sub`, `sup`를 쓸 수 있고 속성은 쓰지 않는다. 분수처럼 태그로 오해할 수 있는 비교 기호의 경우 TeX의 `\lt`나 `\gt`를 쓴다.
- `hint`는 처음 살필 값이나 조건을 짚는 평문 한 문장이다. 답의 값·보기 번호·결론은 풀이로 둔다.
- 객관식 `format`은 `mcq`다. `answer`는 A~D 한 글자다. `options`는 A~D 순서로 `id`, `text`, `why`가 필요하다. 각 오답에 `misconception`과 기존 근거 `source`를 넣는다. 출처 형식은 `note:<topic_id>`, `stt:<date>#<절 또는 찾기 단서>`다. 설명에서 오개념을 드러내고 맞는 판단 조건을 적는다.
- 단답 `format`은 `short`다. `answer`는 `{"canonical":"2/3","accepted":["4/6"]}`처럼 작성한다. 숫자·유한소수·분수는 문자열로 쓰고, 발문에 입력 형식이나 기준을 명시한다. 대표 정답과 허용값은 정확히 같은 값이어야 한다. 분수로 받는다면 기약분수, 소수로 받는다면 자릿수를 명시한다. 자동 채점은 명시한 정답과 허용 표기를 비교한다. 근삿값이 필요한 복잡한 계산은 객관식으로 구성한다. `solution`은 채점 뒤 보여줄 평문 단계의 목록이다.
- 단답의 `compute`는 `{"op":"sum","values":["1/10","3/10"]}`처럼 두 값을 쓰는 `sum`·`product`·`difference`·`ratio` 중 하나를 쓰거나, `{"op":"responsibility","contributions":["1/5","1/10"],"component":1}`처럼 책임도의 기여량과 성분 번호를 적는다. 성분 번호는 1부터 시작한다. `compute`의 값이 발문과 풀이에 실제로 대응하는지 확인한다.

객관식 4문항 이상이면 A~D 정답 수 차이를 1 이하로 맞춘다. 단답은 적은 단계로 손으로 계산할 수 있게 하고, 부정형은 전체의 4분의 1 이하로 둔다. 보기 길이, 정답의 정밀도, 말투가 정답을 드러내지 않는지 검토한다.
